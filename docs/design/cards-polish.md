# D1 카드 아트 마무리

기준: intent/plan.md §9 D1(2026-09-29), intent/spec.md §6.6·FR-12·NF-01/03/07/08·AC-05,
ui-spec.md UX-06/12/13/14/23. 의뢰에 언급된 FR-25~28은 현재 intent/spec.md에 없으므로 새 ID를 만들지 않는다.
시안 A/B·클래식 리마스터는 사용하지 않는다. Commons 0~47 SVG와 원본 SHA-1 매핑은 그대로 유지한다.

## 렌더링 규칙

- 공통 크기: 획득패 26×42, 바닥 44×72, 손패 62×101 CSS px. SVG의 `meet` 비율을 유지하며
  상자와의 비율 차이는 1% 미만이다. 높이·폭 토큰을 함께 바꾸어야 한다. DPR 2/3/3.5 모두 벡터를 직접
  래스터화하고 `image-rendering: auto`를 쓴다. 정수 CSS px도 DPR 3.5와 손패 회전에서는 픽셀 정렬을 보장하지 않는다.
- 월 색인은 불투명 먹색 탭, 12px 글자/16px 행 높이, 좌우 패딩 3px이다. 위·아래 끝에서 바깥으로 1px 뺀다.
  손패 윗줄은 위쪽, 나머지는 아래쪽. 위 오른쪽은 ID 29/40/44, 아래 오른쪽은 8/16/28/36/44이며 나머지는 왼쪽이다.
  광은 원본의 光을 읽고 중복 원 기호를 넣지 않는다. 열끗 ◆, 띠 ▮, 쌍피 두 점은 색 없이도 다르다.
  전체 이름은 `aria-label`로 유지한다. 보너스와 기본 획득패에는 색인을 얹지 않는다.
- 光 5장과 글자가 있는 홍단·청단 6장의 보호 사각형(원본 좌표)은 `CardArt.test.ts`에 고정한다.
  바닥·손패 × 위·아래에서 색인과 보호 영역의 교차 면적은 **0 CSS px²**이다.
  보호 사각형은 글자·光 주변의 여유까지 포함하며 전체 그림을 무가림으로 주장하는 것은 아니다.
- 일반 상태 배지는 카드 위쪽 **2px 밖**, 높이 16px이다. 호출자는 18px 여백을 예약한다.
  국진 쌍피는 겹친 획득패 위의 배지를 없애고 피 그룹 제목에 `국진 쌍피`를 표시한다. 접근성 그룹 이름에도 포함한다.
  그룹 수량·점수는 원래 제목/HUD에 유지한다.
- 뻑은 무더기 위 2px 밖의 12/16px 태그. 바닥 행 간격 20px와 위 여백 18px를 확보한다.
  더미 장수는 뒷면 아래의 별도 행이다. 선택/매칭/피 뺏기 강조는 그림 바깥 **3px 윤곽 + 2px 간격**이다.
  뺏기는 기존 사건 문구와 카드 이동도 함께 유지하며 카드 면에 틴트를 칠하지 않는다.
- 앞·뒷면 실루엣은 바깥 한지색 **1 CSS px outline**. 공통 `box-shadow`는 사용하지 않는다. 뒤집기 대기 카드도 같은 외곽선을 유지한다.
  손패 비활성 불투명도 하한 0.7은 유지한다. 두 줄 손패 윗줄의 명목 노출 높이는 55px이다.

## 획 두께와 대비

SVG 안의 획은 원본 단위 × 실제 스케일의 근삿값이다. 원본 Commons의 미세한 도상 획을 굵게 고치지 않는다.
읽어야 하는 월/점수/상태는 런타임 태그·그룹 제목으로 보완한다. 시스템 글꼴의 개별 획 굵기는 OS에 따라 달라지므로
12/16px 글자 크기와 대비를 보장하고 획의 픽셀 정렬을 보장하지 않는다.

| 요소 | 원본 단위 | 획득패 26px | 바닥 44px | 손패 62px |
|---|---:|---:|---:|---:|
| 앱 외곽선 최소 | CSS | 1px | 1px | 1px |
| 앱 선택선 최소 | CSS | 3px | 3px | 3px |
| 종류 기호 최소 두께 | CSS | 기본 숨김 | 2.88px | 2.88px |
| 자체 카드 안쪽 먹선 | 1.2 | 0.30px | 0.51px | 0.72px |
| 보너스 핵심 숫자·피 획 | 7 | 1.75px | 2.98px | 4.20px |
| 보너스 제목 획 | 2.2 | 0.55px | 0.94px | 1.32px |
| 뺏기 갈고리 주 획 | 3.4 | 0.85px | 1.45px | 2.04px |
| 뒷면 장식 최소 획(정보 아님) | 0.6 | 0.15px | 0.26px | 0.36px |

1 CSS px 외곽선은 DPR 2/3/3.5에서 각각 2/3/3.5 기기 픽셀에 해당한다.
획득패에서는 작은 보너스 제목·갈고리의 세부를 읽게 하지 않고 그룹 가치 합과 접근성 카드 이름으로 정보를 제공한다.
색인 글자 대비 목표 ≥4.5:1, 실루엣·선택선 ≥3:1. `cards.spec.ts`가 브라우저 캔버스의 sRGB 값을 선형화해 계산한다.

| 조합 | Docker Chromium/WebKit 계측 |
|---|---:|
| 월 글자 / 먹색 탭 | 19.18:1 |
| 비활성 월 글자 / 탭 (탁자 위 0.7 합성) | 9.81:1 |
| 한지색 실루엣 / 탁자 | 10.21:1 |
| 선택선 / 탁자 | 7.21:1 |
| 뻑 글자 / 먹색 탭 | 7.95:1 |

안티에일리어싱된 경계 픽셀 자체의 대비가 아니라 전경/배경 색의 대비다. 비활성 탭은 불투명도 0.7로 탁자에 합성한 뒤
4.5:1 이상인지 별도 검사한다. 계측 원본은 실행 산출물 `test-results/**/card-metrics.json`이다.

## 자체 제작 4장과 출처

ID 48/49는 2피, ID 50은 3피(R1/S4). 흰 바탕·먹선·주홍 테와 세트 팔레트, 103.2×168.2 판형을 맞췄다.
48은 먹 언덕, 49는 푸른 물결, 50은 주홍 땅으로 구분한다. 큼직한 가치와 노란 갈고리가 작은 피 패를 끌어오는 도형으로
보너스의 뺏기 기능을 알린다. 이는 B3의 뺏기 기능을 식별하는 도상이며 토글·상황별 발동 여부는 엔진이 결정한다.
뒷면은 주홍 격자·매화 원문과 한지색 외곽이다. Commons의 도상 경로를 복사하지 않은 자체 도형이며 CC0로 제공한다.

사람이 편집하는 원본은 `packages/web/cards-src/`, 배포본은 `public/cards/`이다.
`npm exec -w packages/web -- node scripts/build-cards.mjs --originals-only`로 4장과 저작자 문서를 재생성한다.
Commons 캐시가 필요 없고 0~47 파일을 쓰지 않는다. 최적화 후 파일당 8 KiB 이하, 외부 리소스·텍스트·래스터·필터 없음.
현재 4장 합계 **8,225 B**, Commons **612,763 B**, 카드 합계 **620,988 B**다.
라이선스 화면과 ATTRIBUTION/LICENSE는 단일 저작자 원본에서 CC BY-SA 4.0/CC0/MIT 범위를 구분한다.
라이선스 식별 주소는 텍스트이며 앱의 외부 요청·웹폰트는 없다.

## 검증과 유실 파일

- `CardArt.test.ts` 재작성: 글자/光 보호 영역, 표식 크기, 배지·더미의 무가림, 국진 그룹 제목, 뒷면 정보 비노출.
- `e2e/cards.spec.ts` 재작성: 51개 ID와 엔진 메타데이터·파일 존재·중복 없음, SVGO 재현, 412×915와 DPR 2/3/3.5,
  크기·대비·가로 넘침·외부 요청, 실제 게임판의 태그/카드 무가림·손패 월 표식 노출.
- 유실된 `scripts/card-preview.config.mjs`, `scripts/card-preview.spec.mjs`는 참조가 없어 복원하지 않는다.
  미리보기·PNG 출력을 위 E2E와 `#/dev/gallery/card-sizes`에 통합해 표준 `npm run e2e -w packages/web`에서 실행한다.
- 기존 갤러리 15개 화면(브라우저당)은 `toHaveScreenshot` 픽셀 비교를 유지한다. D1 변경 화면 7개의
  기존 PNG 기준값만 Chromium/WebKit에서 갱신하며 파일별 사유는 PR 본문에 기록한다.
  신규 `card-sizes` 화면은 기준 PNG를 추가하지 않고 접근성 트리·axe·기하/대비와 실행 PNG로 보조 검증한다.
  접근성 트리는 기존 픽셀 비교에 추가하는 검사다. 새 실행 PNG는 gitignore된 `test-results/`, `playwright-report/`에만 남긴다.
- 실기기 결과는 만들지 않는다. S25 Ultra와 iPhone에서의 밝기·글꼴·실제 패널 확인은
  [통합 실기기 절차](../device-test/procedure.md) §7.1 D-CARD-01~03 절차에 따라 사람이 수행한다.

## WebKit 렌더링 비용 확인

추가된 카드 공통 그림자에서 AC-06 회귀가 관측되어 외곽선을 `outline`으로 바꿨다. 판/시스템 부하가 달라질 수 있는
단회 측정이며 절대 성능 비교 실험으로 해석하지 않는다. 모두 같은 Docker WebKit, 기준 배율 1, p50 ≤700ms / 두 번째 최댓값 ≤900ms다.

| 실행 | p50 | 두 번째 최댓값 | 판정 |
|---|---:|---:|---|
| 변경 전 main f697ff4 | 643ms | 732ms | 통과 |
| 카드 공통 블러 + spread 그림자 | 1,014ms | 1,556ms | 실패 |
| 블러만 제거(spread 유지) | 773ms | 960ms | 실패 |
| 최종: 그림자 대신 outline | 625ms | 680ms | 통과 |

이 비교를 위해 쓴 임시 main 체크아웃의 컨테이너·볼륨은 제거했다. 최종 전체 검증 수치는 PR 본문에 기록한다.
