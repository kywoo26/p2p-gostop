# 맞고 UI/UX 규범 — 세로 게임판과 상태 화면

상태: **D2 UI 구현 규범** · 2026-09-29 · 솔로·호스트·게스트 정식 UI 대상. [spec §6](../../spec.md)의 UX-01~25 상세 정의이며 [plan §9 D1·D2](../../plan.md)를 따른다. 규범과 구현 현황(§10·§13)은 구분한다. 카드 방향은 **Commons 48장 유지·렌더링 개선, 보너스 3장·뒷면만 신규 제작**이다. 게임 규칙은 변경하지 않는다.

## 1. 화면 크기와 안전 영역

**UX-01.** 플레이 중의 기준 좌표는 CSS 픽셀이다. Android Galaxy S25 Ultra WebView 세로, iPhone Safari 세로(주소창 확장/축소), 폭 360/390/430px에서 같은 정보와 입력이 유지돼야 한다. **게임판은 `overflow:hidden`이므로 Safari의 하단 탭 막대/주소창이 스크롤로 접히지 않는다. 툴바 표시 상태가 평상 플레이 상태다.** 설계 최소 높이는 다음 실기기 회차에서 세로·툴바 표시 상태의 `window.innerHeight`와 `visualViewport.height`를 재서 확정한다. 그 전에는 390폭 734px(844−약 110), 430폭 822px(932−약 110), 360폭 780px을 보수적 *임시 검증 뷰포트*로 사용한다. 기기 이름으로 레이아웃을 분기하지 않는다. Galaxy의 물리 해상도와 CSS viewport는 동일하다고 가정하지 않는다.

**UX-02.** 게임 루트는 `height: 100dvh; min-height: 0; overflow: hidden`을 기준으로 하며 `100vh`를 높이 정본으로 쓰지 않는다. 툴바 표시 상태의 실측 `innerHeight`가 설계 높이의 기준이며, `visualViewport.height`가 더 작으면 작은 쪽에서 입력 안전성을 재검증한다. 내부의 비게임 화면은 콘텐츠 스크롤을 허용한다. 게임 중 문서 스크롤은 0이어야 한다. 키보드가 필요한 로비만 화면 내부 스크롤을 허용한다. 뷰포트 축소 중 애니메이션 좌표는 다시 측정하고, 선택 중에는 선택 버튼 위치를 고정한다. 세로에서 가로로 돌리면 “세로로 돌려 게임을 계속하세요” 덮개를 띄우고 게임 입력을 잠근다. 세로로 돌아오면 안전 영역을 다시 측정해 복귀한다. 금지 API인 `screen.orientation.lock`은 쓰지 않는다.

**UX-03.** 게임판 패딩은 `max(8px, env(safe-area-inset-top))`, 좌우 `max(8px, env(safe-area-inset-left/right))`, 하단 `max(8px, env(safe-area-inset-bottom))`을 기본으로 한다. 상단 HUD·메뉴는 Dynamic Island/상태 막대 바깥, 손패의 마지막 터치 영역은 홈 인디케이터 위에 둔다. inset이 0으로 보고되는 Safari에서도 최소 8px 여백을 남긴다. Android WebView의 시스템 바 영역은 호스트가 보고하는 실제 inset으로 검증한다. 장식 배경만 안전 영역 끝까지 칠할 수 있다. [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Apple Game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls).

## 2. 게임 화면의 구역

**UX-04.** 판은 위에서 아래로 **양쪽 좌석 HUD/상대 획득패/바닥/선택·동작 구역/내 획득패·진행도/손패**의 6행이다. 선택 구역은 항상 예약된 공간이며, 선택이 없을 때는 “내 차례/상대 차례” 한 줄과 이벤트 레일로 쓴다. 덱은 바닥 왼쪽에 둔다. 획득패는 광·열끗·띠·피 4개 그룹을 항상 같은 순서로 유지하고 카드가 늘어도 그룹 높이를 키우지 않는다.

**UX-05.** 예산은 *임시* `innerHeight`에서 상·하 안전 패딩 34+24=58px, 5개 행 간격 4px×5=20px을 뺀 수치다. 최악의 선택 상태에서 390×734: `734−58−20−(56+44+132+48+168)=208px`; 360×780: `780−58−20−448=254px`; 430×822: `822−58−20−(60+48+144+56+184)=252px`을 바닥에 준다. 390의 바닥은 카드 높이 약 65px×3행+행 간격 4px×2=203px와 세로 여백 최대 5px이다. **실측 툴바 표시 `innerHeight`가 734px보다 작으면** 카드·버튼을 자르지 않고 로비/정산과 다른 별도 저높이 배치를 설계한 뒤 수용 시험을 다시 한다. 우선순위는 손패 유효 터치 영역 → 바닥 카드/무더기 → 선택 버튼 → 양쪽 좌석 점수·잔액·진행도 → 획득패 썸네일 → 장식 여백이다. 압축은 (1) 여백 12→8, (2) 획득패 썸네일 축소, (3) 바닥 카드 44→40(선택 타깃이면 투명 히트 영역 48 유지), (4) 손패 카드 62→48/56과 2줄 정렬(§14.5), (5) 선택 설명을 접고 “자세히”로 확장하는 순서다. 바닥과 손패의 필수 노출·입력 영역을 잘라내거나 페이지를 스크롤하지 않는다. 윗줄의 허용 노출 창과 표식 분리는 §14.5를 따른다. 12개 월 무더기와 뻑 스택은 *그룹당 하나의 셀*로 세며 여러 장은 8~12px 오프셋으로 쌓는다. 대상 선택 시 두 후보를 바닥에 강조하고 선택 구역에 48px 이상의 복제 버튼을 준다.

**UX-06.** 손패 1~5장은 1줄, 6~10장은 2줄이다. 가로 360에서 한 줄 5장의 전체 터치 폭은 좌우 안전 여백 안에 들어야 한다. 두 줄은 위 줄의 카드 구별 가능한 그림·월 표식·최소 48×48 입력 영역이 아래 줄에 가려지면 안 된다. 같은 월은 인접 배치하고 월 순 정렬을 유지한다. 상대 차례에도 카드 면과 월 표식은 읽을 수 있어야 하며 시각적 비활성화의 **불투명도 하한은 0.7**이다(현행 `Card.svelte`도 0.7).

## 3. 겹침·입력·프롬프트

**UX-07.** 쌓임 순서의 단일 토큰은 `board 0 < moving cards 20 < banner 30 < toast 40 < prompt 50 < modal/settlement 60 < menu 70`이다. 같은 계층 간 DOM 순서에 의존하지 않는다. 6개 행 컨테이너는 `transform`, `opacity<1`, `filter`, `isolation`, `contain:paint`, 지정 `z-index` 등으로 **별도 stacking context를 만들면 안 된다**. FLIP이 도착 DOM 자리에서 실행될 때 이동 카드에 z-index 20을 주거나, 재생 중에 루트 이동 오버레이로 승격해 실제 시각 계층을 보장한다. 움직이는 카드는 출발·도착 좌표를 보여 주되 패널 콘텐츠를 가리지 않는다. 메뉴는 최상위이지만 시스템 UI 안전 영역 안에만 있다. 토스트·배너는 `pointer-events: none`; 프롬프트·모달 뒤 게임 입력은 `inert`다.

**UX-08.** 토스트·배너·선택창의 보이는 사각형은 손패의 유효 터치 영역 또는 현재 선택 가능한 바닥 카드와 겹치면 안 된다. 긴 배너는 한 줄로 축약하거나 최대 2줄로 감고 판 중앙의 빈 레일에 둔다. 토스트는 HUD 아래의 알림 레일에 최대 2초 머물며 새 알림이 오면 교체한다; 선택 중에는 프롬프트 위에 겹치지 않고 큐에 보관한다. 배너는 최대 1개만 보여 주고 이벤트 주체(“나/상대”)를 문구와 함께 표시한다.

**UX-09.** 고/스톱은 선택 구역에서 점수·스톱 예상액·위험 요약과 두 버튼을 보인다. 대상 선택은 바닥 후보 강조 + 선택 구역의 카드 라벨 버튼이다. 선택 패널은 화면 중앙에 세로로 떠 손패/내 획득패를 덮지 않는다. 가용 높이가 부족하면 세부 배수표는 접되 예상액과 버튼은 항상 보인다. 손패 끝과 선택 버튼 사이 빈 거리 ≥16px, 버튼 간 ≥8px, 모든 주요 입력 ≥48×48 CSS px; Android dp/iOS pt의 정확한 변환은 실기기 검증 때 확인한다. [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)의 44pt 기준보다 큰 제품 목표다.

**UX-10.** 손패 탭은 한 번만 액션을 보낸다. 애니메이션 스킵은 **빈 바닥 또는 별도 “건너뛰기” 버튼**의 pointerup에서만 수행하고, 같은 포인터 연쇄에서 카드 내기를 금지한다. 프롬프트는 배경 탭·스와이프로 닫지 않는다(규칙상 선택이 필요함). 정보성 토스트는 탭/스와이프로 닫을 수 있고 2초 후 자동 소멸한다. 메뉴/비결정 모달은 닫기 48px 버튼·Escape/뒤로 가기 지원; 재접속 중에는 진행 입력을 잠그되 메뉴·도움말은 연다.

## 4. 시각 시스템

**UX-11.** 사용자 결정(2026-09-29)으로 **A · 사이**를 채택한다. 먹빛 판과 한지색 포인트를 쓰며 한지 사진·천 질감·나뭇결·광택·반복 패턴은 쓰지 않는다. 앱 배경 `oklch(19% .018 170)`, 판 `oklch(24% .025 170)`, 패널 `oklch(28% .025 170)`, 주요 글자 `oklch(95% .025 85)`, 보조 글자 `oklch(76% .025 140)`, 행동 포인트 `oklch(86% .07 85)`, 포인트 위 글자 `oklch(20% .025 160)`를 정본으로 한다. 판은 평평한 면, 패널/버튼 반경12px를 기준으로 하고 장식과 필수 입력 경계를 분리한다(UX-12 대비). 게임판은 다크를 유지한다. **슬로건·감성 문구·세로 텍스트 장식 금지**, 앱 이름·기능·상태·원인/다음 행동·수치만 표시한다. “사이”는 방향 이름이며 앱 슬로건이 아니다. B/C는 기각 기록만 보존하며 선택 테마 기능을 만들지 않는다. [채택 근거/비교 기록](visual-direction.md).

**UX-12.** `tokens.css`에는 색의 **의미**를 기준으로 `bg`, `table`, `surface`, `surface-raised`, `on-surface`, `muted`, `outline`, `primary`, `on-primary`, `danger`, `success`, `focus`, `scrim`, `card-border`, `event-*` 역할을 둔다. 현재 OKLCH 값은 출발점이며 실제 조합은 9장의 대비 기준으로 계측해 확정한다. 색만으로 사건을 알리지 않는다. 탁자 위 분리선·카드 실루엣은 최소 3:1, 텍스트는 보통 4.5:1, 큰 글자 3:1을 목표로 한다. **적색 카드 뒷면도 녹색 탁자와 실루엣 3:1**을 유지해야 하므로 뒷면 둘레에 밝은 한지색 테두리를 둔다(빨강 단독 경계에 의존하지 않음). Material 3의 [color roles](https://m3.material.io/styles/color/roles)는 역할 분리의 참조다.

**UX-13.** 한국어 글꼴은 **Pretendard Variable v1.3.9의 로컬 WOFF2 서브셋 1종**(OFL-1.1)을 채택한다. 수정본 family는 `GostopSans`, 뒤에 `system-ui, -apple-system, 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif`를 둔다. 외부 웹폰트/CDN 요청은 금지하며 시스템의 Noto만 fallback으로 허용한다. 원본/고지 SHA-256은 [고정 manifest](fonts/sources.json)의 Pretendard 항목을 따른다. 실제 UI 코퍼스(오류·선택·정산 포함)의 글리프 누락0, unicode-range와 cmap 일치, 가변 wght/tnum 보존, 고지 원문 동봉을 gate로 삼는다. 사용자 이름의 서브셋 밖 글자는 시스템 fallback이다. 제목32/40, 홈 제목40/48, 구역18/24, 본문16/22, 필수 상태14/20, 보조12/16 CSS px; 점수24/30, 정산금액48/58. HUD는 §14 높이 계약을 위해 점수20/24·필수 숫자14/20을 유지한다. 숫자는 `tabular-nums`와 고정 열/우측 정렬, 필수 점수·금액·선택 문구는14px 미만 금지. **Safari aA 페이지 확대**는 글자만이 아니라 CSS viewport도 줄이므로 확대 뒤의 `innerHeight`를 다시 재고 6행을 재배치한다. **Android 시스템 글꼴 크기·WebView `textZoom`**은 계산된 글자 크기를 확인한다. 일반 화면은 200% 텍스트를 재배치한다. 게임판의 밀집 숫자·칩은 기본 크기의 **125%까지만 판 안에서 키우고**, 150~200% 확대에서는 같은 점수·잔액·진행도·카드 이름·행동을 제공하는 확대 정보/선택 패널(내부 스크롤, 문서 스크롤 없음)을 사용한다. 그 패널의 텍스트는 200%로 읽고 모든 행동을 완료할 수 있어야 한다. 아이콘은 번들 SVG 또는 CSS 도형이며 “메뉴”, “닫기”, “더미”처럼 접근성 이름을 가진다. 화살표·색상만으로 기능을 표시하지 않는다.

## 5. 동작과 재생

**A 화면 적용 기록:** [a-screens-validation.md](a-screens-validation.md). #46/#47 구현은 위6행·HUD 예산을 사용하며 작은 화면의 획득패는 §14 UX-H02b대로 상세에 접는다. 선 고르기8장은 분배 전 빈 손패 행을 회수해 선택224px를 사용한다. 아래 §8·§14의 기존 구현 격차/후속 소유 기록보다 이 적용 기록의 검증 범위가 최신이며, #51 확대·실기기 실측 대기는 그대로다.

**UX-15.** 아래 단계·정지 시간(ms)은 `spec.md` §6.4와 같은 시간표다. 기본값은 보통, 빠름은 AC-06용 기존 이동 표(정지 0), 매우 빠름은 빠름 ×0.6이다. 정지는 해당 이동이 끝난 뒤 다음 이벤트를 커밋하기 전까지다. 복잡한 빠름 턴은 이동 시간 계획 합을 500ms로 비례 압축한다. 선택 없는 빠름 턴의 탭→이벤트 재생·최신 뷰 스냅 완료 목표는 ≤700ms다. 보통의 대표 경로인 **낸 카드 매칭 → 더미 공개 → 획득** 계획은 약 1.6~2.2초이며, 이 경로를 고정한 E2E p50 허용 범위는 1.4~2.4초다.

| 단계·정지 (ms) | 보통(기본) | 빠름 | 매우 빠름 |
|---|---:|---:|---:|
| 손패 → 바닥 이동 / 닿은 뒤 정지 | 270 / 100 | 120 / 0 | 72 / 0 |
| 매칭 강조 / 매칭 뒤 정지 | 100 / 200 | 80 / 0 | 48 / 0 |
| 더미 뒤집기 / 공개 뒤 정지 | 280 / 250 | 140 / 0 | 84 / 0 |
| 획득 이동 / 획득 뒤 정지 | 300 / 160 | 160 / 0 | 96 / 0 |
| 여러 장 획득 스태거 | 40 | 30 | 18 |
| 피 뺏기 이동 | 350 | 200 | 120 |

E2E는 시드 1의 저장 세션으로 손패·바닥·더미 첫 장과 낼 카드를 고정하고, 예상 이벤트 열을 확인한 뒤 412×915에서 각 경로를 3회 재생해 p50을 단언한다. 다음은 **계측 허용 범위**이며 단계 시간의 합계 규범을 대체하지 않는다. 뻑 배너는 카드 이동과 겹쳐 표시된다.

| 선택 없는 고정 턴 경로 | 빠름 p50 (ms) | 보통 p50 (ms) |
|---|---:|---:|
| 매칭 없음: 내기 → 뒤집기 → 두 장 바닥에 놓기 | 250~700 | 1,000~1,600 |
| 매칭+획득: 낸 카드 매칭 → 뒤집기 → 2장 획득 | 450~700 | 1,400~2,400 |
| 사건 배너: 내기 → 뒤집기 → 뻑 표시 | 250~700 | 1,000~1,600 |

카드 이동 이징은 `cubic-bezier(.2,.8,.2,1)`, 짧은 등장/퇴장은 `ease-out`/`ease-in`이다. 한 턴 안에서 낸 카드 → 바닥 매칭 → 더미 공개 → 뒤집힌 카드의 매칭 → 획득의 공간 순서를 보존한다. 사건 배너는 카드 이동과 겹치되 카드 위로 내려오지 않는다. 판 종료·선 고르기 문구 읽기 대기(배너 시간 ×2)는 카드 턴 계측과 별개이며 스킵하면 즉시 끝난다. §6 UX-18~19의 사건·EngineEvent 표와 §8 EventBanner 행에 남은 350/160(+30)/200ms, 분배 1.2s, 턴 700ms는 **빠름 기준**이다. 선택한 속도의 시간에는 위 표가 우선한다. 스킵·즉시 모드·동작 줄이기에서는 이동과 정지가 모두 0이며 AI 생각 간격도 건너뛸 수 있다. [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion), [Material 3 motion](https://m3.material.io/styles/motion/overview).

**UX-16.** 재생 중 입력은 잠그고 스킵은 현재 애니메이션을 마지막 프레임으로 보내며 남은 이벤트를 즉시 반영한다. 새 이벤트가 들어오면 이전 시퀀스를 끝 상태로 수렴시킨 뒤 새 시퀀스를 재생한다. 선택창이 열린 순간 카드 이동은 끝나 있어야 한다. 상대 턴은 동일한 카드 경로로 보여 주고 HUD에 “상대 차례” 또는 “생각 중…”을 안정적으로 표시한다; 무한 펄스·회전 로더를 쓰지 않는다. 상대 손패 내용은 공개하지 않는다.

**UX-17.** `prefers-reduced-motion: reduce`에서는 FLIP·스케일·플래시·자동 스태거를 0으로 하고 카드의 최종 배치, 사건 문구, 점수 변화는 그대로 보여 준다. 효과 강도 “끔”도 같은 시각 경로를 쓴다. 움직임은 `transform`·`opacity`만, `will-change`는 움직이는 카드에만 일시적으로 준다. 점수 숫자, 남은 더미 수, 차례 라벨, 내 손패의 읽는 방향, 배경/탁자, 정산 금액은 흔들거나 카운트업하지 않는다. 반복 동작·초당 3회 초과 플래시는 금지한다. WCAG 2.3.3은 AAA지만 제품 목표로 따른다.

## 6. 사건 효과 규범

## 9. 접근성과 검증 기준

**UX-23.** WCAG 2.2 AA를 기본으로 한다: 일반 텍스트 4.5:1, 큰 텍스트 3:1(1.4.3), 필수 경계·아이콘 3:1(1.4.11), 초점 가림 없음(2.4.11), 최소 타깃 24×24 CSS px(2.5.8). 본 제품은 플레이 카드와 주요 버튼에 더 엄격한 48×48px와 8px 간격을 쓴다. 손패 두 줄의 *보이는 히트 영역*도 재야 한다. 색각에 관계없이 사건 이름·선택 상태·차례를 글자와 모양으로 알린다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

**UX-24.** 키보드와 스크린리더 순서는 상단 상태→상대→내 HUD→상대 획득패→바닥→선택→내 획득패/진행도→손패→메뉴다. 프롬프트 등장 시 제목으로 초점을 옮기고 선택 뒤 원래 제어로 돌린다. 고/스톱에는 선택 결과의 금액을 버튼 이름에 포함한다. 바닥 후보는 “9월 청단, 먹기”처럼 월·종류·행동을 읽는다. 반복 점수 갱신은 단일 `role=status`에서 짧게 합쳐 읽고 배너와 토스트가 동시에 같은 내용을 중복 발화하지 않는다. 터치 드래그에만 의존하지 않는다. Safari aA 200%와 Android 시스템 글꼴·`textZoom` 200%에서 UX-13의 확대 패널로 동일 정보·행동에 접근하고, 시스템 다크 모드·모션 감소·효과 끔을 화면별로 확인한다.

**UX-25.** 수용 스냅샷은 Chromium+WebKit의 **360×780/390×734/430×822 임시 툴바 표시 뷰포트**와 툴바 숨김 390×844/430×932에 대해 기본/손패10+바닥12/고스톱/대상/긴 배너+토스트/연결 끊김/가로 방향/200% 텍스트다. 각 경우 문서 스크롤 0, 손패와 후보의 유효 입력 사각형 ≥48×48, 프롬프트·토스트·배너와 유효 입력의 교차 면적 0, safe-area 침범 0을 검사한다. **재생 중 이동 카드의 실제 페인트 순서**를 DOM 행 경계에서 스크린샷으로 확인하고, 상위 행의 stacking context가 z20을 가두지 않는지 E2E에서 검사한다. 실기기 Safari 툴바 표시/숨김 `innerHeight`·`visualViewport.height`, Dynamic Island, 하단 탭 막대와 손패의 교차, Android 시스템 바/진동은 `docs/device-test/` 절차에 따라 사람이 확인하고 그 결과만 기록한다.

**UX-H01a / 높이 예산과 긴 값.** §2 UX-05의 안전 패딩 58px·행 간격 20px·획득패/손패 높이는 유지한다. 기본 점수판은 2×28px(410px 이상 2×30px), 테두리 포함 높이다. 잔액의 쉼표·단위 포함 문자열이 어느 좌석이든 10자를 넘으면 양쪽 모두 **42px×2=84px**로 전환한다. 각 좌석 첫 줄(24px)은 이름/점수/고/배수, 둘째 줄(18px)은 정확한 금액(14px 이상)을 오른쪽 정렬한다. 두 좌석의 열 시작점은 동일하다. 이름만 말줄임하고 전체 이름은 접근성 이름에 남긴다. 금액 반올림·축약·삭제는 금지한다.

| 뷰포트 | 기본 HUD / 선택 | 긴 금액 HUD / 선택 | 선택 시 바닥(둘 다 동일) | 바닥 카드 3행 필요 |
|---|---|---|---|---|
| 390×734 | 56 / 132 | 84 / 104 | `734−58−20−(84+44+104+48+168)=208` | 203px |
| 360×780 | 56 / 132 | 84 / 104 | `780−58−20−448=254` | 203px |
| 430×822 | 60 / 144 | 84 / 120 | `822−58−20−(84+48+120+56+184)=252` | 236px |

선택 없는 행동 행도 56→28px(넓은 폭 64→40px)로 재배분해 바닥 여유를 보존한다. 긴 금액 모드에서 선택 상세 설명만 접고 핵심 선택/예상액·48px 버튼·8px 버튼 간격은 유지한다. 최대 안전 정수 금액과 긴 이름을 함께 검증한다. 확대는 §9·#51의 확대 패널 계약을 따른다. 이 표는 #46/#47의 예약 행 구현이 따라야 할 예산이며 HUD PR은 해당 이슈 완료를 주장하지 않는다.

**UX-H02 / 대비·판과의 관계.** 시각 스킨은 디자인 리드 결정 후 토큰으로 교체한다. 아래 값은 임시 대비 기준이며 컴포넌트에 색·그림자·테두리 장식을 하드코딩하지 않는다. 새로운 토큰은 HUD 전용이며 `--dur-*`는 바꾸지 않는다. HUD는 불투명한 짙은 청록 표면, 판은 기존 어두운 녹색, 내 점수만 연한 한지색 강조. 카드보다 큰 밝은 면/광택/반복 패턴/박스 그림자를 넣지 않는다. 일반 글자와 수치는 4.5:1 이상, 경계는 인접 표면·판 모두에 3:1 이상을 실측한다.

### 14.5 손패 그림·표식 분리 (Galaxy 사용자 피드백, 2026-09-29)

**UX-H05 / FR-46~50.** 게임판 compact 손패의 월은 기존 Card의 모서리 배지로 표시한다(윗줄은 위 모서리, 아랫줄은 아래 모서리; 기존 `markSide`의 도상 보호 규칙 유지). 보조 상태·강조선은 그림 밖에 둔다. 각 카드 바로 아래 **16px 높이의 전용 띠**에 **14px 상태 단어**만 표시하고 월 숫자를 반복하지 않는다. 원 SVG와 Card는 변경하지 않는다. 색만으로 판단하지 않도록 아래 형태를 함께 쓴다. 일반 Card/바닥/획득패 표식은 이 변경 범위가 아니다.

기본 표식(없음/먹기/확정)과 행동 배지(폭탄/흔들)는 **별도 축**이다. 묶음 라벨 옆에도 확정/먹기 형태를 함께 표시할 수 있다. 월 단위의 동일 상태를 라벨에 합치고 각 카드 접근성 이름에는 개별 상태를 보존한다. 접근성 이름에도 확정 여부와 행동을 함께 남긴다. `unseenCards(PlayerView)`는 엔진에 있으나 현재 BoardView에는 확정 결과가 없다. UI에서 가짜 PlayerView를 만들거나 숨은 손패·더미를 읽지 않는다. #81/#87/#80 연결 시 같은 월 잔존/고갈·이미 획득/내가2장·공개된 상대 흔들기 패(`unseenCards`에서 제외됨) 경계 사례를 조사 규범과 대조한다. 힌트 단계 설정/판정 완료를 이 시각 슬롯 PR에서 주장하지 않는다.

**UX-H06 / 폭탄 묶음 인계.** `HandVisualGroup {id, kind, cards}`와 `selectedGroup`은 액션·시간축에서 분리된 표시 계약이다. 같은 group ID의 카드3개에 `data-hand-group`을 두고, 누르는 동안 세 슬롯의 바깥 선·표식 띠를 함께 강조한다. 사건 PR은 기존 `data-card-id` 이동 기준점과 이 그룹을 연결해 3장 묶음 이동을 설계한다. 현재 폭탄 확인/한 장만/취소 액션은 유지한다. **팝업 없는 직접 내기 전환은 인터뷰 확정 뒤 별도 행동 계약**이며 현재 탭에서 폭탄을 자동 실행하지 않는다. #86 이동·스킵·reduced-motion 시간축은 변경하지 않는다.

기존 FLIP의 이동 중 표시(`will-change`)가 있는 카드만 그림 창의 잘림을 해제하고 z20으로 그린다. 그 카드의 아래 표식은 잠시 숨겨 이동 그림을 가리지 않는다. 완료·취소 시 기존 FLIP이 표시를 회수하면 창과 표식이 복구된다. 별도 타이머/애니메이션을 만들지 않으며 `Hand.visual.test.ts`에서 창 밖 실제 hit-test·취소 복구를 검증한다.

묶음 강조선은 점선이고 실제 키보드 초점 카드의 선은 기존 focus 토큰의 실선이다. 세 장이 함께 강조되어도 초점이 있는 한 장을 구분한다.

브래킷은 전달받은 실제 장수를 감싼다. 기존 옵션의 2장 폭탄·4장 흔들기도 같은 단어로 표시하고 판정은 재구현하지 않는다(`rules-commercial.md` §12 E10/E12 유지).

1. 필수 선택/키보드 초점 → 합법/매칭 → 내 행동 가능 → 조건부 사건·박. 같은 카드에 윤곽은 하나; 나머지는 선택 행 텍스트에 합친다. 기본/상세 변경은 액션을 전송하지 않는다.
2. 보조는 §3 board 계층에 속한다. banner 30/toast 40/prompt 50을 추가로 만들지 않으며 독자 타이머·소리·진동·알림 큐를 만들지 않는다. 선택 중에는 그 선택 관련 설명만 노출하고 일반 사건 알림은 §3 큐에서 대기한다. 시간 예산은 §5 그대로.
3. 상태 요약 발화는 §9의 단일 `role=status`를 통해 한 번. 숫자마다 live region 금지. 초점 이동 없이 정보 갱신, pointer 없는 키보드도 같은 설명. 색만으로 확정/가능 구별 금지; 감소 모션은 정적 표시, 200%는 §9 확대 패널로 동일 정보.

### 15.5 설정·조언·기록 계약

**UX-A03 / FR-46·49~50.** 신규 기본값은 ‘끔’이다([조사 §4](../research/play-assist.md#4-힌트-강도모드별-재조사와-결정)). 핵심 HUD/기본 진행도/필수 선택은 모든 단계에 남는다. P2P에서는 추천 수/후보 순위/효용·승률 추정 등 강한 조언을 UI·계산·전달 모두에서 비활성화하며 welcome 협상 옵션을 만들지 않는다. 공개 문턱·박 산술·조건문은 추천 없이 두 좌석에 동일 기능으로 제공한다. 실제 숨은 정보는 솔로도 금지한다.

### 14.8 화면 검토 보완 (2026-09-29, #104)

선택이 없는 예약 행도 낮은 대비의 장식 테두리 슬롯으로 유지한다. 왼쪽은 ‘내 차례’/‘상대 차례 · 생각 중’ 등 상태, 오른쪽은48px 이상 ‘판 정보’ 버튼을 같은 행에 정렬한다. 장식 테두리는 입력 경계를 대신하지 않는다. 펼쳐진 내/상대 획득패의 광·열끗·띠·피 제목은 같은 소형 칩(12px, 높이20px)으로 통일한다.

고/스톱 위험 요약은 `goStop.steps`에 제공된 `piBak`/`gwangBak`만 표시한다. 하나면 ‘피박 위험’ 또는 ‘광박 위험’, 둘이면 ‘피박·광박’(접근성 이름 ‘피박·광박 위험’)이다. 미제공 시 추측하지 않는다. 상한 적용은 패널 제목 줄에 두어 최소 화면에서도 위험·금액·48px 버튼을 보존한다.
