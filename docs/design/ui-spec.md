# 맞고 UI/UX 규범 · 세로 게임판과 상태 화면

> **#123 개정안:** §16은 main `1287e7f` 대비 리뷰·사용자 승인 전 제안이다. 기존 UX-09·HUD 계약은 비교를 위해 유지한다. P2P 기본 10초·호스트 끄기/조정·솔로 제외는 확정, 배치·초과 행동·시계 세부값은 권고다.

상태: **D2 UI 구현 규범** · 2026-09-29 · 솔로·호스트·게스트 정식 UI 대상. [spec §6](../../spec.md)의 UX-01~25 상세 정의이며 [plan §9 D1·D2](../../plan.md)를 따른다. 규범과 구현 현황(§10·§13)은 구분한다. 카드 방향은 **Commons 48장 유지·렌더링 개선, 보너스 3장·뒷면만 신규 제작**이다. 게임 규칙은 변경하지 않는다.

## 1. 화면 크기와 안전 영역

**UX-01.** 플레이 중의 기준 좌표는 CSS 픽셀이다. Android Galaxy S25 Ultra WebView 세로, iPhone Safari 세로(주소창 확장/축소), 폭 360/390/430px에서 같은 정보와 입력이 유지돼야 한다. **게임판은 `overflow:hidden`이므로 Safari의 하단 탭 막대/주소창이 스크롤로 접히지 않는다. 툴바 표시 상태가 평상 플레이 상태다.** 설계 최소 높이는 다음 실기기 회차에서 세로·툴바 표시 상태의 `window.innerHeight`와 `visualViewport.height`를 재서 확정한다. 그 전에는 390폭 734px(844−약 110), 430폭 822px(932−약 110), 360폭 780px을 보수적 *임시 검증 뷰포트*로 사용한다. 기기 이름으로 레이아웃을 분기하지 않는다. Galaxy의 물리 해상도와 CSS viewport는 동일하다고 가정하지 않는다.

**UX-02.** 게임 루트는 `height: 100dvh; min-height: 0; overflow: hidden`을 기준으로 하며 `100vh`를 높이 정본으로 쓰지 않는다. 툴바 표시 상태의 실측 `innerHeight`가 설계 높이의 기준이며, `visualViewport.height`가 더 작으면 작은 쪽에서 입력 안전성을 재검증한다. 내부의 비게임 화면은 콘텐츠 스크롤을 허용한다. 게임 중 문서 스크롤은 0이어야 한다. 키보드가 필요한 로비만 화면 내부 스크롤을 허용한다. 뷰포트 축소 중 애니메이션 좌표는 다시 측정하고, 선택 중에는 선택 버튼 위치를 고정한다. 세로에서 가로로 돌리면 “세로로 돌려 게임을 계속하세요” 덮개를 띄우고 게임 입력을 잠근다. 세로로 돌아오면 안전 영역을 다시 측정해 복귀한다. 금지 API인 `screen.orientation.lock`은 쓰지 않는다.

**UX-03.** 게임판 패딩은 `max(8px, env(safe-area-inset-top))`, 좌우 `max(8px, env(safe-area-inset-left/right))`, 하단 `max(8px, env(safe-area-inset-bottom))`을 기본으로 한다. 상단 HUD·메뉴는 Dynamic Island/상태 막대 바깥, 손패의 마지막 터치 영역은 홈 인디케이터 위에 둔다. inset이 0으로 보고되는 Safari에서도 최소 8px 여백을 남긴다. Android WebView의 시스템 바 영역은 호스트가 보고하는 실제 inset으로 검증한다. 장식 배경만 안전 영역 끝까지 칠할 수 있다. [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Apple Game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls).

## 2. 게임 화면의 구역

**UX-04.** 2026-09-30 사용자 상용 맞고 레퍼런스 결정으로 이전 HUD·판 구역 배치를 대체한다. 위에서 아래로 **상단 한 줄(판·점당 금액·상대 이름·메뉴) / 상대 획득패 / 상대 HUD / 중앙 바닥·더미 / 내 HUD / 내 획득패 / 전체 앞면 손패**다. 문턱·개수 상세와 진행도는 메뉴의 판 정보 시트로 옮긴다. 획득패는 광·열끗·띠·피 순서, 종류 라벨 12/400, 카드당 6px 오프셋으로 최대 4장만 그리고 마지막 모서리에 전체 장수 하나를 표시한다. 카드 종류와 피 가치는 접근성 이름과 상세에서 유지한다.

**UX-05.** 손패·바닥은 폭48px, 획득 요약은 폭32px이며 높이는 폭/0.614다. 사용자가 손패와 획득 진영의 역할 구분을 요청해 전체48px 규칙을 개정했다. **획득 스택 오프셋→HUD 여백 순으로 높이를 절약하며, 손패·바닥 크기의 상태별 변경·문서 스크롤·획득패 숨김은 금지한다.** 상단48px, 획득패 각각 카드높이+18px, HUD 각각52px, 손패 한 줄102px/두 줄180px, 6개 행 간격8px(높이760px 이하는6px), 나머지 높이가 중앙이다. 안전 영역은 실제 inset 및 상34/하24 경계로 검증한다. 바닥은 **5열×3행 격자를 기본 경로**로 하고 가운데7번 셀에 더미를 둔다. 채움 순서는 더미 좌/우→상/하→대각→바깥 열이며 같은 월은 독립 인접 셀(가로 우선, 다음 세로, 과밀 조합에서 대각 연결)로 모은다. 빈 슬롯은 그리지 않는다. 셀 피치는 카드 폭의1.25배, 행 피치는 카드 높이+폭의25%이며 높이가 부족하면 행 간격을 줄인다. 블록 전체는 중앙 영역의 세로 가운데에 둔다. 카드 ID로 결정한 ±4°·±3px 흩뿌림은 회전된 경계까지 자기 셀 안에 들어오는 범위에서만 적용하며 선택 후보는 움직이지 않는다. 앞면100%·셀 교차0을 검사한다. 바닥14장까지는 전부 독립 셀이다. 15장 이상일 때만 같은 월을 두 장씩5px 오프셋으로 접고, 그래도14칸을 넘는 극단 경계에서는 같은 월3장 묶음을 허용한다(선택 후보는 항상 독립 셀). 과밀 예외는 별도 캡처한다.

**UX-06.** 최종 사용자 시인성 정정(2026-09-30): 손패와 바닥은 **모든 카드의 앞면100%가 보여야 한다**. 이전 한 줄·40% 노출안은 뒤 카드 식별이 어렵다는 실사용 피드백으로 폐기한다. 손패6장 이하는 한 줄, 7~10장은 같은 달을 나누지 않는 두 줄로 펼치며 기울기·행 겹침·그림 창 절단은 없다. 카드48px 폭과 전체 높이를 입력 영역으로 쓴다. 주 버튼(button=0) 누름에서 미리보기, 처음 누른 카드 안에서 놓을 때만 한 번 실행한다. 보조 버튼·다른 카드·영역 밖 놓기·pointercancel은 선택을 해제하고 제출하지 않는다. 키보드 Enter/Space와 폭탄 Shift+Enter는 유지한다. 취소·뷰 교체·재생 잠금은 액션을 무효화한다. 키보드 초점은4px 들림과 링을 보인다. 바닥은 같은 월도 독립 셀로 펼친다. 손패·바닥 월 숫자·종류 배지는 없고 도상·월/종류 aria-label은 유지한다. 비활성 불투명도 하한0.7.

## 3. 겹침·입력·프롬프트

**UX-07.** 쌓임 순서의 단일 토큰은 `board 0 < moving cards 20 < banner 30 < toast 40 < prompt 50 < modal/settlement 60 < menu 70`이다. 같은 계층 간 DOM 순서에 의존하지 않는다. 7개 행 컨테이너는 `transform`, `opacity<1`, `filter`, `isolation`, `contain:paint`, 지정 `z-index` 등으로 **별도 stacking context를 만들면 안 된다**. FLIP이 도착 DOM 자리에서 실행될 때 이동 카드에 z-index 20을 주거나, 재생 중에 루트 이동 오버레이로 승격해 실제 시각 계층을 보장한다. 움직이는 카드는 출발·도착 좌표를 보여 주되 패널 콘텐츠를 가리지 않는다. 메뉴는 최상위이지만 시스템 UI 안전 영역 안에만 있다. 토스트·배너는 `pointer-events: none`; 프롬프트·모달 뒤 게임 입력은 `inert`다.

**UX-08.** 토스트·배너·선택창의 보이는 사각형은 현재 유효한 손패 또는 선택 가능한 바닥 카드와 겹치면 안 된다. 고/스톱 중앙 패널이 비활성 바닥 일부를 덮는 것은 UX-09의 의도된 예외다. 긴 배너는 한 줄로 축약하거나 최대 2줄로 감고 판 중앙의 빈 레일에 둔다. 토스트는 HUD 아래의 알림 레일에 최대 2초 머물며 새 알림이 오면 교체한다; 선택 중에는 프롬프트 위에 겹치지 않고 큐에 보관한다. 배너는 최대 1개만 보여 주고 이벤트 주체(“나/상대”)를 문구와 함께 표시한다.

선택창은 손패 영역 하단의 `dialog`와 `aria-modal=true`로 표시하고 열린 동안 창 밖 게임판을 `inert`로 잠근다. 진입 시 제목에 초점을 옮기고 Tab/Shift+Tab은 설명 스크롤 영역을 포함해 선택 제어와 상위 게임 메뉴 진입점 사이에서 순환한다(UX-24). 메뉴 버튼은 aria-owns로 선택창의 접근성 소유 관계에 포함하고, 기존 z70 메뉴/Android Back은 유지한다. 상위 네이티브 메뉴가 열리면 선택창의 초점 가두기를 중단하고 메뉴 자체의 잠금·복귀를 따른다. 필수 선택은 Escape로 닫지 않는다. 선택/취소 후 원래 제어가 유효하면 복귀하고, 제거/비활성이면 남은 손패 또는 판 정보로 복귀한다. 다음 선택창으로 이어지면 새 창에 초점을 유지한다. 재생 중인 퇴장 창은 입력을 받지 않으며 새 창의 배경 잠금을 먼저 풀지 않는다.

**UX-09.** 사용자 추가 레퍼런스 결정에 따라 고/스톱은 중앙 패널로 표시한다. 바닥 일부는 가리되 손패·획득패·제한시간은 유지한다. 제목은 “고 하시겠습니까?”, 예상 정산액을 그 아래, 왼쪽 스톱·오른쪽 다음 고 횟수 버튼을 둔다. 엔진이 제공한 피박/광박 위험을 함께 표시한다. 상시 획득패 스탬프의 추가 적용은 PA-06에서 제공 데이터와 비가림 검증을 전제로 추적한다. 선택 필수, 닫기 없음, 48px 버튼 두 개와 초점 순환을 유지한다. 바닥 대상 선택은 후보만 발광하고 나머지를 흐리게 하며 후보 카드에서 직접 탭한다. 상단 한 줄에 짧게 안내하고 별도 시트를 띄우지 않는다.

**UX-10.** 손패 탭은 한 번만 액션을 보낸다. 애니메이션 스킵은 **빈 바닥 또는 별도 “건너뛰기” 버튼**의 pointerup에서만 수행하고, 같은 포인터 연쇄에서 카드 내기를 금지한다. 프롬프트는 배경 탭·스와이프로 닫지 않는다(규칙상 선택이 필요함). 정보성 토스트는 탭/스와이프로 닫을 수 있고 2초 후 자동 소멸한다. 메뉴/비결정 모달은 닫기 48px 버튼·Escape/뒤로 가기 지원; 재접속 중에는 진행 입력을 잠그되 메뉴·도움말은 연다.

## 4. 시각 시스템

**UX-11.** 먹빛 판·한지 본문·황동 강조의 A 방향을 유지하며 장식을 최소화한다(2026-09-30 사용자 결정). 글자12/14/16/24px, 굵기400/600만, 자간0, 숫자 tabular-nums. 보조는 한지60%의 시각 강도(일반 텍스트 대비4.5:1 하한 우선), 변동은 적/청록과 +/−를 함께 쓴다. 상자 반경4px·동일1px 경계, 그림자는 카드에만 한 종류다. 그라디언트·발광 글자·눈에 띄는 질감·금선 프레임·가죽 받침·비네트는 쓰지 않는다. 슬로건·em dash 금지. 현실적인 판 캡처와 MAX_SAFE 경계 fixture를 분리한다. 외부 앱 참고 캡처는 저장소에 포함하지 않는다.

**UX-12.** `tokens.css`에는 색의 **의미**를 기준으로 `bg`, `table`, `surface`, `surface-raised`, `on-surface`, `muted`, `outline`, `primary`, `on-primary`, `danger`, `success`, `focus`, `scrim`, `card-border`, `event-*` 역할을 둔다. 현재 OKLCH 값은 출발점이며 실제 조합은 9장의 대비 기준으로 계측해 확정한다. 색만으로 사건을 알리지 않는다. 탁자 위 분리선·카드 실루엣은 최소 3:1, 텍스트는 보통 4.5:1, 큰 글자 3:1을 목표로 한다. **적색 카드 뒷면도 녹색 탁자와 실루엣 3:1**을 유지해야 하므로 뒷면 둘레에 밝은 한지색 테두리를 둔다(빨강 단독 경계에 의존하지 않음). Material 3의 [color roles](https://m3.material.io/styles/color/roles)는 역할 분리의 참조다.

## 5. 동작과 재생

**이전 A 화면 적용 기록(#104, PA-05 개정 전):** [a-screens-validation.md](a-screens-validation.md). #46/#47 구현은 위6행·HUD 예산을 사용하며 작은 화면의 획득패는 §14 UX-H02b대로 상세에 접는다. 선 고르기8장은 분배 전 빈 손패 행을 회수해 선택224px를 사용한다. 아래 §8·§14의 기존 구현 격차/후속 소유 기록보다 이 적용 기록의 검증 범위가 최신이며, #51 확대·실기기 실측 대기는 그대로다.

**UX-15.** 아래 단계·정지 시간(ms)은 `spec.md` §6.4와 같은 시간표다. 기본값은 보통, 빠름은 AC-06용 기존 이동 표(정지 0), 매우 빠름은 빠름 ×0.6이다. 정지는 해당 이동이 끝난 뒤 다음 이벤트를 커밋하기 전까지다. 복잡한 빠름 턴은 이동 시간 계획 합을 500ms로 비례 압축한다. 선택 없는 빠름 턴의 탭→이벤트 재생·최신 뷰 스냅 완료 목표는 ≤700ms다. 보통의 대표 경로인 **낸 카드 매칭 → 더미 공개 → 획득** 계획은 약 1.6~2.2초이며, 이 경로를 고정한 E2E p50 허용 범위는 1.4~2.4초다.

E2E는 시드 1의 저장 세션으로 손패·바닥·더미 첫 장과 낼 카드를 고정하고, 예상 이벤트 열을 확인한 뒤 412×915에서 각 경로의 첫 워밍업을 제외한 7회 실측 p50과 단계 계획 합을 따로 기록한다. Chromium은 아래 경로별 범위와 AC-06의 700ms를 엄격히 단언하고, hosted CI WebKit은 #103에서 확인한 실행 편차(매칭+획득 p50 로컬 562ms→CI 888ms) 때문에 벽시계만 기록하며 계획 상한·경로는 검증한다. 다음은 **계측 허용 범위**이며 단계 시간의 합계 규범을 대체하지 않는다. 뻑 배너는 카드 이동과 겹쳐 표시된다.

카드 이동 이징은 `cubic-bezier(.2,.8,.2,1)`, 짧은 등장/퇴장은 `ease-out`/`ease-in`이다. 한 턴 안에서 낸 카드 → 바닥 매칭 → 더미 공개 → 뒤집힌 카드의 매칭 → 획득의 공간 순서를 보존한다. 사건 배너는 카드 이동과 겹치되 카드 위로 내려오지 않는다. 판 종료·선 고르기 문구 읽기 대기(배너 시간 ×2)는 카드 턴 계측과 별개이며 스킵하면 즉시 끝난다. §6 UX-18~19의 사건·EngineEvent 표와 §8 EventBanner 행에 남은 350/160(+30)/200ms, 분배 1.2s, 턴 700ms는 **빠름 기준**이다. 선택한 속도의 시간에는 위 표가 우선한다. 스킵·즉시 모드·동작 줄이기에서는 이동과 정지가 모두 0이며 AI 생각 간격도 건너뛸 수 있다. [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion), [Material 3 motion](https://m3.material.io/styles/motion/overview).

**UX-16.** 재생 중 입력은 잠그고 스킵은 현재 애니메이션을 마지막 프레임으로 보내며 남은 이벤트를 즉시 반영한다. 새 이벤트가 들어오면 이전 시퀀스를 끝 상태로 수렴시킨 뒤 새 시퀀스를 재생한다. 선택창이 열린 순간 카드 이동은 끝나 있어야 한다. 상대 턴은 동일한 카드 경로로 보여 주고 HUD에 “상대 차례” 또는 “생각 중…”을 안정적으로 표시한다; 무한 펄스·회전 로더를 쓰지 않는다. 상대 손패 내용은 공개하지 않는다.

**UX-17.** `prefers-reduced-motion: reduce`에서는 FLIP·스케일·플래시·자동 스태거를 0으로 하고 카드의 최종 배치, 사건 문구, 점수 변화는 그대로 보여 준다. 효과 강도 “끔”도 같은 시각 경로를 쓴다. 움직임은 `transform`·`opacity`만, `will-change`는 움직이는 카드에만 일시적으로 준다. 점수 숫자, 남은 더미 수, 차례 라벨, 내 손패의 읽는 방향, 배경/탁자, 정산 금액은 흔들거나 카운트업하지 않는다. 반복 동작·초당 3회 초과 플래시는 금지한다. WCAG 2.3.3은 AAA지만 제품 목표로 따른다.

**UX-20a. 정산 표시.** #100이 제공한 밀기/받기 가능 여부·정산 금액·포기 점수·다음 판 배수를 그대로 표시한다. UI에서 재판정하지 않는다. 제목24px·확정 금액48/58px·tabular-nums, 먹빛 상세 면과 한지색 주요 행동을 쓴다. 받기/밀기·다음 판·종료·재충전 버튼은 하단 안전 영역 안에 최소48px(구현56px)로 유지하고 상세 영역만 세로 스크롤한다. 상세는 이름 있는 region과 키보드 초점/스크롤을 제공한다. 민 판의 정산0·포기점수·다음판 배수는 점선 경계+문구로 구분하고, 승자 선택 대기에는 실행 가능한 받기/밀기를 만들지 않는다. 360×780·390×734·430×822·412×915에서 버튼 가림0·가로넘침0, 장문 잔액/이름·나가리·파산을 검사한다. 금액 카운트업/전문 질감 스킨은 이 화면 PR에 추가하지 않는다.

솔로 밀기 대기(#131, U15)는 최종 재생과 스냅 뒤 ‘판 결과’에서 승패·사유·점수·배수·‘받을 경우 예상 금액’·미정산 안내와 ‘결과 확인’만 보여준다. 확인 후 ‘받기·밀기 선택’으로 전환하며 CPU 승자는 그때 결정을 요청한다. 예상 잔액 변화 표는 숨기고, 확인한 결과는 최종 정산 재생 완료까지 유지한다. 확인/선택 단계 전환은 결과 제목으로 초점을 옮겨 이전 Enter가 새 행동을 실행하지 않게 한다. 저장 복원은 미확인 상태로 시작한다. 확정 정산의 다음 판은 명시 선택이며 임의 지연·자동 확인은 없다. 보통/빠름/동작 줄이기/스킵의 상태 순서는 같다.

**UX-21.** 로비 QR은 실제 생성된 값만 표시한다. QR 로드 실패·핫스팟 권한 거절·iPhone의 “인터넷 없음” 안내는 서로 다른 원인/행동 문구를 갖는다. 세션 종료·무효는 확인 절차를 두고, 재접속 실패는 자동으로 새 게임을 시작하지 않는다. 모든 비게임 상태 화면은 안전 영역 안에서 세로 스크롤을 허용한다.

## 9. 접근성과 검증 기준

**UX-23.** WCAG 2.2 AA를 기본으로 한다: 일반 텍스트 4.5:1, 큰 텍스트 3:1(1.4.3), 필수 경계·아이콘 3:1(1.4.11), 초점 가림 없음(2.4.11), 최소 타깃 24×24 CSS px(2.5.8). 주요 버튼은 48×48px, 손패의 입력은 UX-06을 따른다. 손패는 UX-06의 앞면100%·48px 입력·같은 카드 놓기을 측정한다. 색각에 관계없이 사건 이름·선택 상태·차례를 글자와 모양으로 알린다. [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

**UX-24.** 키보드와 스크린리더 순서는 상단 상태→상대→내 HUD→상대 획득패→바닥→선택→내 획득패/진행도→손패→메뉴다. 프롬프트 등장 시 제목으로 초점을 옮기고 선택 뒤 원래 제어로 돌린다. 고/스톱에는 선택 결과의 금액을 버튼 이름에 포함한다. 바닥 후보는 “9월 청단, 먹기”처럼 월·종류·행동을 읽는다. 반복 점수 갱신은 단일 `role=status`에서 짧게 합쳐 읽고 배너와 토스트가 동시에 같은 내용을 중복 발화하지 않는다. 터치 드래그에만 의존하지 않는다. Safari aA 200%와 Android 시스템 글꼴·`textZoom` 200%에서 UX-13의 확대 패널로 동일 정보·행동에 접근하고, 시스템 다크 모드·모션 감소·효과 끔을 화면별로 확인한다.

**UX-25.** 수용 스냅샷은 Chromium+WebKit의 **360×780/390×734/430×822 임시 툴바 표시 뷰포트**와 툴바 숨김 390×844/430×932에 대해 기본/손패10+바닥12/고스톱/대상/긴 배너+토스트/연결 끊김/가로 방향/200% 텍스트다. 각 경우 문서 스크롤 0, 손패와 후보의 유효 입력 사각형 ≥48×48, 프롬프트·토스트·배너와 유효 입력의 교차 면적 0, safe-area 침범 0을 검사한다. **재생 중 이동 카드의 실제 페인트 순서**를 DOM 행 경계에서 스크린샷으로 확인하고, 상위 행의 stacking context가 z20을 가두지 않는지 E2E에서 검사한다. 실기기 Safari 툴바 표시/숨김 `innerHeight`·`visualViewport.height`, Dynamic Island, 하단 탭 막대와 손패의 교차, Android 시스템 바/진동은 `docs/device-test/` 절차에 따라 사람이 확인하고 그 결과만 기록한다.

## 13. 현재 웹 구현 지도 (docs/ui.md에서 통합)

경로는 `packages/web/src/` 기준. `p2p/role.ts`가 루프백 origin은 호스트 앱, 비루프백은 게스트로 정한다. `?role=host|guest`·`?relay=host:port`는 개발/E2E 덮어쓰기다. 호스트는 해시 라우팅, 게스트는 `#g=<토큰>&n=<이름>`을 쓰므로 화면 상태로 이동한다. `?speed=instant`는 저장하지 않는 E2E 즉시 모드다.

초기 Docker 계측(2026-09-28)은 Chromium p50 568~571ms·최대 596ms, WebKit p50 578~635ms·최대 599~737ms였고, 2코어 CI WebKit은 p50 660ms·최대 849ms까지 흔들렸다. 계획 상한을 540→500ms로 낮춘 근거이며 실기기 측정값은 아니다.

AC-06 계측은 click timeStamp→이벤트 재생·스냅 완료를 기록한다. 현재 솔로 E2E는 위 고정 3경로에서 Chromium 빠름 p50≤700ms·두 번째 최대≤900ms와 경로별 범위를 단언하며, hosted CI WebKit은 벽시계를 기록만 한다. 계획 상한 단위 테스트도 있으나 P2P는 시간 기록만 하므로 #58, 실기기 예산은 #70에서 검증한다.

남은 웹 기능: 로비 준비·P2P 기록·판 무효 UI(#44, abortRound API는 이미 구현), 규칙 토글/화폐 단위/잔액(#62), 진동·효과 강도(#49), AI 생각 시간(#65), 리플레이 내보내기(#71). 효과음은 Web Audio 합성 최소판이다.

## 14. 점수판·현황판 (HUD)

**UX-H01 / FR-40·42.** 상대 점수판은 상대 획득패 위, 내 점수판은 내 획득패 위에 둔다. 한 패널에 두 진영 점수를 모으지 않는다. 진행도는 해당 획득패에 인접한다. 입력/규칙/표시 속성 판정은 바꾸지 않고 같은 SeatBar를 각각 이동한다. 근거는 사용자 C 결정과 [조사](../research/play-assist.md).

**UX-H01a / 높이 예산과 긴 값.** §2의 공통 카드 스케일과 높이 예산을 따른다. 잔액은 24/600, 변동은14/600과 +/−, 점수24/600, 이름14/400, 보조 라벨·카운트12/400이다. 1억 미만은 만 단위 정수+나머지4자리, 1억 이상은 억+만, 1조 이상은 조+억으로 축약하며 정확한 값은 aria-label·판 정보에 유지한다. 0고·배수는 점수 옆, 제한시간 남은 초는 이름 줄 오른쪽에 둔다. 실시간 정산 예상액·위험은 고/스톱 중앙 패널에 표시한다.

긴 금액 모드에서도 선택 핵심/예상액·48px 버튼·8px 버튼 간격을 유지한다. 최대 안전 정수 금액과 긴 이름을 함께 검증한다. 확대는 §9·#51의 확대 패널 계약을 따른다. 기존56/60/84px 합산 HUD와6행 예산은 이 개정으로 대체한다.

### 14.5 손패 그림·표식 분리 (Galaxy 사용자 피드백, 2026-09-29)

**UX-H05 / FR-46~50.** 최신 사용자 시인성 정정을 따라 UX-06의 전체 앞면 배치를 적용한다. 한 줄 겹침 부채꼴은 폐기한다. 같은 달 묶음은 인접하고 두 줄 경계에서 나누지 않는다. 손패·바닥 스케일은48px, 상태에 따른 scale·width·height 변경 없음. 폭탄/종은 카드 왼쪽 위20px 메달리온, 묶음 바깥2px 플레이트를 유지한다. 월/종류 배지·반복 텍스트는 없으며 도상·aria-label은 유지한다. 먹기 황동 단선·확정 청록 이중선은 유지한다. 펄스는 앱 루트 `data-effect-intensity="strong"`일 때만, reduced-motion에서는 정적이다.

**#114/#115 표시 속성 계약:** 손패 `data-hand-cue=matchable|secured`, `data-hand-action=bomb|shake|chongtong`(멤버 전부), `data-hand-group=<month>`; 바닥 그룹 `data-hand-link=bomb|chongtong`. 힌트 끔이면 미제공한다. CSS는 이 속성만 소비한다. 총통 후보4장은 기존 강한 가장자리 표현을 유지하며 폭탄으로 오인할 그림은 붙이지 않는다. 게임 판정을 재현하지 않는다. #114가 묶음 비분할 정렬을 담당한다.

먹기·확정은 그림 창 바깥 가장자리로 표현한다. 들림은 정적 상태차이며 새 전환 시간/상시 점멸이 없다. 단선/이중선·2/4px 높이 차이를 색과 함께 사용한다. 기본 매칭/확정 상태와 폭탄/흔들기 묶음은 별도 축이다. 2장 폭탄·4장 흔들기 옵션도 전달받은 멤버 각각에 해당 그림을 표시하며 규칙은 바꾸지 않는다(`rules-commercial.md` §12 E10/E12).

화면 단어를 제거해도 각 카드 **aria-label에는 월·종류·확정 여부·폭탄/흔들기 전체 설명을 유지**한다. 초보자용 범례는 첫 실행 요약 #62(#135 통합)에서 다룬다. UI가 숨은 상대 손패·더미를 읽거나 가짜 PlayerView를 만들지 않는다. #144 반례: unseen에 M이 없어도 상대 공개 패에 M이 있으면 확정이 아니라 일반 매칭이다. 판정 연결은 #114/#115/#80 소유이며 이 시각 PR에서 완성으로 주장하지 않는다.

**UX-H06 / 묶음 인계.** 기존 `HandVisualGroup {id, kind, cards}`·`selectedGroup`·`data-hand-group`과 탭 시3장 바깥 점선 강조는 유지한다. 실제 키보드 초점의 실선과 구분한다. 카드 입력/직접 폭탄 흐름은 #111/#112/#136 소유이며 스킨에서 액션을 변경하지 않는다. 사건 PR은 기존 data-card-id 이동 기준점으로 그룹 이동을 연결한다. #86 시간축·스킵·reduced-motion 계약은 그대로다.

FLIP의 will-change가 있는 카드만 기존 그림 창 잘림을 해제하고 z20으로 그린다. 그동안 정적 들림·발광·동작 그림을 회수해 이동 좌표와 그림을 보호하고, 완료/취소 뒤 원래 상태로 복구한다. 별도 타이머/큐를 만들지 않는다. 최소4화면의 손패10장·선택 동시·무가림·초점·이동 취소 검사를 유지한다.

### 15.2 우선순위·알림·접근성

1. 필수 선택/키보드 초점 → 합법/매칭 → 내 행동 가능 → 조건부 사건·박. 같은 카드에 윤곽은 하나; 나머지는 선택 행 텍스트에 합친다. 기본/상세 변경은 액션을 전송하지 않는다.
2. 보조는 §3 board 계층에 속한다. banner 30/toast 40/prompt 50을 추가로 만들지 않으며 독자 타이머·소리·진동·알림 큐를 만들지 않는다. 선택 중에는 그 선택 관련 설명만 노출하고 일반 사건 알림은 §3 큐에서 대기한다. 시간 예산은 §5 그대로.

### 15.5 설정·조언·기록 계약

**UX-A03 / FR-46·49~50.** 신규 기본값은 ‘기본’이다(#115 합의; 이전 조사 §4는 검토 이력). 핵심 HUD/기본 진행도/필수 선택은 모든 단계에 남는다. P2P에서는 추천 수/후보 순위/효용·승률 추정 등 강한 조언을 UI·계산·전달 모두에서 비활성화하며 welcome 협상 옵션을 만들지 않는다. 공개 문턱·박 산술·조건문은 추천 없이 두 좌석에 동일 기능으로 제공한다. 실제 숨은 정보는 솔로도 금지한다.

### 14.8 화면 검토 보완 (2026-09-29, #104)

선택이 없는 예약 행도 낮은 대비의 장식 테두리 슬롯으로 유지한다. 왼쪽은 ‘내 차례’/‘상대 차례 · 생각 중’ 등 상태, 오른쪽은48px 이상 ‘판 정보’ 버튼을 같은 행에 정렬한다. 장식 테두리는 입력 경계를 대신하지 않는다. 펼쳐진 내/상대 획득패의 광·열끗·띠·피 제목은 같은 소형 칩(12px, 높이20px)으로 통일한다.

고/스톱 위험 요약은 `goStop.steps`에 제공된 `piBak`/`gwangBak`만 표시한다. 하나면 ‘피박 위험’ 또는 ‘광박 위험’, 둘이면 ‘피박·광박’(접근성 이름 ‘피박·광박 위험’)이다. 미제공 시 추측하지 않는다. 상한 적용은 패널 제목 줄에 두어 최소 화면에서도 위험·금액·48px 버튼을 보존한다.

### 2026-09-30 시인성 정정의 실제 높이 예산

손패·바닥48px(높이78.18px), 획득 요약32px(높이52.12px)다. 360×780과412×840의 기본 패딩 상하16px, 상단48px, 양쪽 획득 각각70.12px(라벨18 포함), 양쪽 HUD 각각52px, 손패180px, 행 간격8px×6=48px이다. 중앙 실가용 높이는 각각 **243.76px / 303.76px**이며 바닥은 이 사각형 안에서 비겹침 배치한다. 아래 패가 보이지 않는 문제를 해결하기 위해 한 줄 부채꼴 개정은 철회하고 기존 UX-06의 비겹침 두 줄을 유지한다. safe-area가 늘어나는 경우는 별도 측정하며 이 계산을 실기기 inset 검증으로 대체하지 않는다.

### 2026-09-30 레퍼런스 결정 이력

- 레퍼런스는 패·획득·사건·돈·점수 식별에 참고한다. 5×3 바닥 격자와 셀 내부 흩뿌림을 유지하며 같은 달은 독립 셀에 둔다(회전±4°·오프셋±3px 범위, 14슬롯 초과 때만 5px 겹침).
