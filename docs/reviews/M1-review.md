## 1. 판정 요약

**M1 완료 인정(조건부).** 12장 45개 항목 중 42개가 원문과 일치하고, 불일치로 볼 만한 것은 3건(모두 "해석 필요" 성격)이다. 엔진은 순수·결정적이며, `reduce`는 `legalActions` 밖의 액션을 받지 않고, 10,000판 불변식과 커버리지 기준을 충족한다. AC-01·AC-02 통과.

조건:
1. 흔들기 거절 정보 누출(중요 F-1)은 M4 전에 고친다.
2. 해석 3건(국진 자동 모드 뺏기 면제, 3뻑의 나가리 배수 제외, `baseMultiple`의 기본점수 = 1)은 사용자 결정을 받는다(3장 해석 9·13·14, 6장 F-2·F-5·F-7).
3. M2 ISMCTS가 쓰기 전에 결정화(determinization) API를 엔진에 추가한다(중요 F-3).

spec 쪽에서 **심각** 1건(S-1: NP-06 commit-reveal이 분배 **전에** 시드를 공개하면 게스트가 호스트 손패와 더미 순서를 전부 계산할 수 있음)을 찾았다. M1 코드 결함은 아니지만 엔진의 "시드 → 전체 분배" 결정성과 바로 맞물리므로 여기 적는다.

### 5.2 M3 웹 UI (spec 4.5, FR-12~18)

- 이벤트: spec 4.5의 25종 모두 있고 `Redealt`·`FirstPicked`·`FirstPickTie`·`CardDrawn`·`GukjinPlaced`·`Hudang`이 더 있다. 모든 이벤트에 `seq`·`seat`·`cards`.
- 차이: spec은 `Settled(ledgerEntry)`인데 엔진은 `Settlement`(점수)만 낸다. 원장은 호출자가 `applySettlement`로 만든다. spec 문구를 고치거나 웹이 원장 항목 이벤트를 따로 만든다(경미).
- 낸 카드가 먹지 못하고 바닥에 놓이는 경우 전용 이벤트가 없다(`Matched`가 없는 것으로 추론해야 함). 애니메이션 큐가 추론 규칙을 복제하게 된다(경미 F-8: `Placed` 이벤트 추가 권장).
- FR-12 "먹게 될 바닥 카드 예고": UI가 월 매칭을 다시 구현해야 한다. 엔진에 `matchPreview(view, card)` 같은 도우미를 두면 규칙이 한 곳에 남는다(경미).
- 프롬프트: `pending` 종류(pickFirst·chongtong·play·shake·target·gukjin·goStop)로 모든 모달을 그릴 수 있다.

### 5.3 M4 프로토콜 (NP-02·03·06·07)

- 직렬화: `GameState`·`PlayerView`·`EngineEvent` 모두 JSON 안전(Map/Set/undefined 없음). 크기는 NP-07 이내.
- 순번: `eventSeq`와 이벤트 `seq`가 있고, `redactEvent`는 순번을 유지해 NP-03 재동기화에 쓸 수 있다.
- **FR-14 스톱 미리보기를 게스트가 계산할 수 없다**: `previewStop`은 `GameState`를 받는데, `PlayerView`의 `SeatView`에는 `gukjinAsPi`(묻기 모드 선택)가 없다. 호스트가 `goStop` 프롬프트일 때 뷰에 `stopPreview`를 넣어 주거나, 뷰로 계산하는 함수가 필요하다(중요 F-4).
- 신뢰할 수 없는 입력: `reduce(state, null)`은 `TypeError`. protocol 층에서 스키마 검증(zod/mini)을 반드시 거친다(경미 F-9).
- **S-1(심각, spec)**: NP-06은 "분배 직전 원문을 공개"한다. 엔진은 `newRound(rules, seed)`로 덱 전체가 결정되므로, 게스트가 분배 전에 두 난수를 알면 호스트 손패·더미 순서·앞으로의 뒤집기를 모두 계산할 수 있다. 권고 순서: 호스트가 H(h)를 먼저 보냄 → 게스트가 g 원문을 보냄 → 호스트가 seed = f(h, g)로 분배 → **판이 끝난 뒤** h를 공개 → 게스트가 H(h) 확인 후 `replay`로 분배를 검증.

## 7. 총평과 권고

### 판정: **M1 완료 인정(조건부)**

규칙 구현의 정확도가 높고(45개 중 42개 일치, 나머지 3개도 원문이 모호한 곳), 순수성·결정성·합법 수 단일 진실원·커버리지 모두 기준 이상이다. 조건은 1장의 세 가지다.

### M2가 기대기 전 상위 조치

1. **F-3** `determinize`·`unseenCards` API와 왕복 속성 테스트(ISMCTS의 전제).
2. **F-1** 흔들기 거절 누출 수정 + 누출 속성 테스트(AI-01 "정보 은닉 테스트"도 이 뷰에 기댄다).
3. **F-2·F-5·F-7** 사용자 결정 3건(국진 자동 뺏기, 3뻑 이월, 기본점수 정의)을 받아 엔진·벡터 반영. AI 가중치 조정(M2) 전에 끝내야 튜닝을 다시 하지 않는다.
4. **F-4** `PlayerView.stopPreview`(M3 솔로에는 필요 없지만 AI의 고/스톱 판단과 M4 게스트 FR-14가 같은 값을 쓰게).
5. **F-11** 속성 테스트 보강(불변성·불법 액션·누출), 기본 1,000판.
