# 통합 실기기 검증 절차 — Galaxy 호스트·솔로 / iPhone Safari

## 0. 준비

1. GitHub Releases의 검증할 **v0.2.x APK**를 내려받아 설치하고, 태그·커밋·파일 이름을 위 표에 적는다. 같은 서명의 APK로 덮어쓰기 설치한다. 두 기기의 VPN을 끄고, Android의 Wi-Fi를 켠다. 비행기 모드 회차는 비행기 모드를 켠 뒤 Wi-Fi만 다시 켠다.
2. Android에서 앱을 연다. 곧바로 웹 **홈**(친구와 대전 / 혼자 연습 / 기록 / 설정 / 진단)이 보이고 아래쪽에 빌드 해시가 있다. 이 해시를 위 표에 적는다.

## 1. 방 열기 (Android)

1. 홈에서 **친구와 대전**을 누른다. **방 열기** 화면이 나온다.
2. **핫스팟 켜기**를 누른다. 근처 기기 권한 안내가 나오면 허용한다(허용하면 앱이 핫스팟을 스스로 이어서 켠다). 잠시 뒤 "핫스팟 · 켜짐"과 이름·비밀번호·주소(`http://192.168.x.y:17777/`), **Wi-Fi 접속 QR**과 **게임 주소 QR**이 보인다.
3. 핫스팟이 실패하면 휴대폰 설정에서 시스템 핫스팟을 직접 켜거나 두 기기를 같은 Wi-Fi에 연결하고 **주소만 표시**를 누른다. "같은 Wi-Fi의 누구나 들어올 수 있습니다" 경고(NF-06)가 보여야 한다.
4. 규칙(표준/정통/아케이드)·점당 금액·내 이름을 확인한다. 시작 잔액은 점당 금액에 따라 자동으로 바뀐다. 게스트가 없으면 **시작** 버튼은 꺼져 있다.

## 2. 참가 (iPhone)

1. 카메라로 **Wi-Fi QR**을 찍어 연결한다. "인터넷 연결 없음"이 나오면 **인터넷 없이 사용**을 고른다(취소하면 끊긴다). Wi-Fi 이름이 방 열기 화면과 같은지 본다.
2. 카메라로 **게임 주소 QR**을 찍어 Safari로 연다. 아무것도 누르지 않아도 **게임 참가** 화면(이름 입력)이 나와야 한다.
3. 이름을 적고 **입장**을 누른다. **대기실**에 호스트 이름·내 이름·규칙·점당·시작 잔액이 보인다. 주소창의 주소 끝에 `#g=…&n=…`(세션 토큰)이 붙는다.
4. Android 방 열기 화면의 접속자에 "이름 · 연결됨"이 뜨고 **시작**이 켜진다. 규칙이나 점당을 바꾸면 iPhone 대기실 값도 곧바로 바뀌는지 본다.
5. (선택) 다른 폰이나 새 Safari 탭으로 같은 주소를 연다. 나중에 연 창이 연결을 가져가고 먼저 연 창에는 "다른 창에서 접속 중"과 **다시 연결**이 뜬다(4001, 자동으로 서로 밀어내지 않음). 원래 창에서 **다시 연결**을 누르면 되찾는다.

## 3. 한 판

1. Android에서 **시작**을 누른다. 양쪽이 게임판으로 바뀌고 첫 판은 **선 고르기**(카드 한 장 고르기)부터 한다. 양쪽 모두 고른다.
2. 분배 애니메이션 뒤 내 차례에 카드를 탭해 낸다. 상대 차례에는 "생각 중…"이 보이고 상대의 수가 같은 애니메이션으로 재생된다. 스킵은 아래 §7의 현재 동작·개정 규범을 구분해 확인한다.
3. 선택이 필요한 경우(바닥 같은 월 2장, 흔들기, 폭탄, 국진, 고/스톱)는 작은 창으로 묻는다. 고/스톱 창의 점수·배수·스톱 금액을 적는다.
4. 판이 끝나면 양쪽에 **정산** 화면이 뜬다. 승자·점수 분해·배수·금액·잔액이 양쪽에서 같은지 본다. iPhone 정산 화면 아래에 "셔플 공정성 검증 통과"가 나와야 한다.
5. iPhone에서 **다음 판**을 누르면 "호스트가 다음 판을 시작하기를 기다리는 중"이 보이고 Android 정산 화면에 "(이름) 준비 완료"가 뜬다. Android에서 **다음 판**을 누르면 다음 판이 분배된다.
6. 오른쪽 위 **☰** 메뉴: 계속하기 / 설정 / 홈으로(대전은 계속) / 진단·로그 / 대전 끝내기(한 번 더 눌러 확인). 홈에서는 맨 위 **대전으로 돌아가기**로 같은 판에 돌아온다.

## 4. 끊김과 복귀

1. iPhone 화면을 10초 잠갔다가 풀고 Safari로 돌아온다. 5초 안에 같은 판이 다시 보이고 입력이 되는지 적는다. 1분 잠금도 반복한다.
2. 게임 중 iPhone Safari 탭을 닫았다가 방문 기록에서 같은 주소(`#g=…` 포함)를 다시 연다. 이름을 다시 묻지 않고 같은 판으로 돌아와야 한다.
3. iPhone이 끊긴 동안 Android에는 "(이름) 연결 끊김 — 돌아오기를 기다리는 중"이 보이고 카드를 낼 수 없다. 3분이 넘으면 **계속 기다리기 / 세션 종료**를 묻는다.
4. Android 전원 버튼으로 화면을 1분 끈 뒤 켠다. 같은 판이 유지되는지 본다. 홈 화면으로 나가 1분 기다린 뒤 핫스팟 알림(하나뿐인지)을 눌러 돌아온다.
5. 게임 중 Android **뒤로 가기**를 누르면 "진행 중인 게임을 나가시겠습니까?" 확인이 떠야 한다. **계속하기**를 고른다.
6. (선택) Android 앱을 완전히 닫았다가 다시 열고 **친구와 대전** → **이어하기**를 누른다. 저장된 판(진행 중이면 그 판)이 되살아나고, iPhone이 같은 주소로 돌아오면 이어서 둘 수 있다.

## 5. 진단·로그

1. iPhone: ☰ → **진단·로그** → **호스트로 로그 보내기**. "호스트로 N줄 보냈습니다"가 나온다.
2. Android: ☰ → **진단·로그**. 게스트 로그가 "게스트 로그 (업로드)" 아래에 합쳐져 보인다. **로그 공유**로 Android 공유 시트가 열리는지, **기기 진단**이 네이티브 진단 화면을 열고 뒤로 가기로 같은 게임에 돌아오는지 본다.

## 6. 연결 경계·과거 미확인 항목 (AC-00·AC-08·AC-09, NF-04~06)

- A: 비행기 ON 뒤 Wi-Fi ON, B: 비행기 OFF·모바일 데이터 ON, C: 시스템 핫스팟 또는 같은 Wi-Fi에서 주소만 표시. A/B 성공해도 C를 한 번 수행한다. 비행기 ON에서 시스템 핫스팟이 막히면 그 사실을 기록한다.
- 각 경로에서 §1~5를 반복한다. 시작 직후와 재시작 뒤 IP가 핫스팟 인터페이스인지 확인한다. VPN `tun0`·기존 `wlan0`·셀룰러·`p2p-…`가 잘못 선택되면 IP·인터페이스·로그 시각을 기록한다. SSID·비밀번호 변경 여부도 기록한다.
- 캡티브 시트 표시 여부는 예/아니오와 실제 버튼 이름으로 남긴다. QR 실패 시 Wi-Fi 수동 접속 및 `http://`를 포함한 주소 입력을 시도한다. 현재 판 5판 이상 연속 완료 여부를 기록한다.
- 주변 기기 권한 거부 상태에서 주소만 표시·LAN 경고를 확인한다. 핫스팟 켜기 실패 후 재시도·중지와 알림 상태를 확인한다. 현재 중지는 주소 모드로 내려가며 서버를 유지하므로 구형 스모크의 서비스 종료 기대값을 쓰지 않는다.
- 게스트 로그 전송 빈도 제한(5초), 호스트 공유 파일·본문 수신 여부, 1분 호스트 잠금/백그라운드·게스트 잠금 복귀를 확인한다. 가능하면 1시간 플레이 전후 양쪽 배터리·밝기·기기 온도·플레이 모드를 기록한다(#70).
- 오류 코드·권한·IP·연결 단계에서 멈추면 화면 문구와 로그를 보낸다. 비밀번호·세션 토큰은 외부 보고에서 가린다.

## 7. 솔로·표시·입력 (FR-12·FR-14·FR-18, MN-01~05, UX-01~25)

1. Galaxy 홈 → 혼자 연습: 난이도·규칙·금액 확인 → 한 판 → 정산 → 기록 → 홈·이어하기. 새 게임 확인, 저장 실패/손상 안내, 잔액·즉시 정산·재충전 일치는 #63~65의 미완 항목도 기록한다.
2. 카드 앞면은 손패·바닥·획득패에 보이고 더미만 뒷면이어야 한다(#5). 손패는 월 순, 같은 월은 광·열끗·띠·피 순, 보너스는 끝이며 보충 후에도 유지돼야 한다(#7).
3. 상대 애니메이션 중 손패를 눌렀다 떼어도 그 연쇄로 카드가 나가지 않는지 5회 확인한다(#8). 개정 UX-10은 빈 바닥/전용 버튼만 스킵하도록 요구하며 범위 제한은 아직 #52 구현 대상이다. 빈 바닥에서 시작해 손패 위에서 떼는 경우도 확인한다.
4. 양쪽 점수·광/고도리/단/피 진행도·뻑/흔들기/폭탄 횟수, 사건 주체, 피 뺏기 방향을 확인한다(#9). 국진이 쌍피일 때 피 칸과 HUD 숫자·정산 국진 표시가 같아야 한다(#4, PR #54).
5. 고/스톱·대상·국진·흔들기·폭탄·총통 선택에서 필수 숫자와 손패·후보를 읽고 누를 수 있어야 한다. 메뉴·Android 뒤로 가기·홈 복귀에서 같은 판이 유지되는지 확인한다.
6. 기본 **보통**으로 솔로 플레이하며 낸 카드→매칭→더미 공개→획득과 사건(뻑·쪽·따닥·쓸·뺏기)을 눈으로 따라갈 수 있는지 본다(UX-15). 판 종료·선 고르기 읽기 대기 중 탭 스킵 뒤 다음 화면·입력이 바로 가능한지 확인한다. AI 생각 중 탭하면 최소 생각 간격이 사라지는지, 모션 감소에서는 이동·정지가 없는지 확인한다(UX-16~17). 빠름·매우 빠름으로 바꿨다가 다시 열어 저장값도 확인한다.

### 7.1 D1 카드 확인 (사람이 수행)

Galaxy S25 Ultra는 우선 412×915 CSS px·DPR 3.5를 예상값으로 삼되 실제 `innerWidth/innerHeight/devicePixelRatio`를 기록한다.
`#/dev/gallery/card-sizes`와 실제 게임판을 기본 밝기/낮은 밝기, 기본 글꼴/125%에서 각각 확인한다.
Docker 브라우저 계측은 `docs/design/cards-polish.md`에 별도로 기록하며 실기기 결과는 [결과 로그](results.md)에 D-CARD ID별로 기록한다.

| ID | 조작과 판정 |
|---|---|
| D-CARD-01 | 손패·바닥의 광 5장과 홍단/청단 글자를 확인한다. 위/아래 월 색인과 배지가 光·띠 글자를 가리지 않고, 상대 차례의 0.7 불투명도에서도 읽을 수 있어야 한다. |
| D-CARD-02 | 48/49/50을 2피/2피/3피로 구분하고 갈고리 도상으로 보너스를 알아본다. 작은 획득패에서는 피 그룹 합계와 국진 쌍피 제목을 읽는다. 뻑·더미 수·선택/뺏기 강조가 카드 면을 가리지 않아야 한다. |
| D-CARD-03 | 녹색 탁자에서 붉은 뒷면 외곽이 분명하고 얇은 무늬가 번쩍이지 않는지 확인한다. 카드 넘김·겹침 중 선명도, 화면 읽기의 카드 이름, 오프라인 라이선스 출처 목록도 확인한다. |

## 8. 모바일 경계·접근성 (UX-01~25, NF-03·NF-08)

- 세로 Safari 툴바 표시/숨김별 CSS 폭, `window.innerHeight`, `visualViewport.height`, safe-area를 기록한다. 360×780/390×734/430×822는 실측 전 임시 검증값이다. 게임판은 스크롤로 툴바가 숨지 않으므로 툴바 표시 상태가 기준이다.
- 손패 10장·바닥 12월 그룹+뻑·긴 배너·토스트·선택이 겹치는 상태를 준비한다. 실제 판에서 만들 수 없으면 개발 fixture 실행 경로를 기록하고 재현하지 못한 항목은 미실시로 둔다.
- 문서 스크롤·잘림·입력 가림·safe-area 침범 0, 노출 터치 영역 ≥48×48px, 간격 ≥8px를 확인한다. Safari 최하단 손패 경계와 하단 탭 막대·상단 HUD와 Dynamic Island의 교차 면적을 기록한다.
- Safari aA 100%/200%, Android 시스템 글꼴·WebView `textZoom`, 다크 모드·밝기·모션 감소, 소리·효과 강도·Android 진동을 각각 확인한다. 설정이 없으면 미구현으로 기록한다(#49). 소리·진동 없이도 사건 문구와 점수 정보가 남아야 한다.
- 화면 읽기·키보드/접근성 탐색으로 후보·고/스톱 선택, 제목 초점과 반환 초점, 겹침 중 읽기 순서를 확인한다. 세로→가로에서는 안내·입력 잠금, 복귀 때 선택 보존을 확인한다.
- 재접속·호스트 부재·연결 교체·파산·종료에서 원인과 복구 행동을 읽을 수 있어야 한다. 종료 뒤 죽은 다음 판 버튼이 남는지 확인한다(#50).
