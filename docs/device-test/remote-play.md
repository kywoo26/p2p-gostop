# 원격 대전 검증 절차 (사용자 답변 반영, 최종 승인 대기·사람 실행)

관련: spec §13 AC-RP-01~06 · plan RP-03A/B·04·05C·07 · [조사·공식 근거](../research/remote-play.md). **2026-09-29 사용자 제공 결과로 Funnel 기본 WebSocket 통과 확인.** 아래 전체 수용 절차는 구현 후 사람이 실행한다. 자동 E2E는 실기기/Funnel 지원의 증거로 대체하지 않는다.

| 준비 | 확인 |
|---|---|
| 버전 | APK·정적 웹·PC 중계 commit/release·Tailscale 버전, Galaxy/iPhone/Mac OS·WebView/Safari 버전 기록 |
| 망 | Galaxy 셀룰러와 상대 별도 Wi-Fi/셀룰러. 상대 Tailscale 앱/로그인 없이 공개 URL 접속. 집 PC Linux 또는 Windows/WSL2/Docker와 Tailscale 실행 위치 기록 |
| 공개 전 | 강화된 인증 중계만 사용. 기존 relay-dev를 그대로 Funnel에 연결하지 않음. 전용 루프백 포트·MagicDNS·HTTPS 인증서·PC 한정 funnel 속성·기본 제공 ts.net URL 확인 |
| 비용 | 무료 Personal/Free 계정·유료 기능 없음 확인. PC 전원/절전·회선/Windows 업데이트 일정 확인. 토큰·IP 전체·QR 비밀을 결과에 첨부하지 않음 |

### RP-03A/B PC 운영 검증 기록 칸 (사람 실행)

## 선택적 RP-A 검증 절차 — 미실시·우선 구현 안 함

B안의 선행 검증이 아니다. A안을 별도 선택·구현한 뒤 사람만 실행하고 결과를 제공한다.

| 확인 | 합격 기준 |
|---|---|
| Galaxy 노드 공유·상대 Tailscale 설치/계정·별도 망 | PC/Funnel 없이 브라우저에서 Galaxy `http://100.x:17777/`로 웹·guest WS 접속, 공유 MagicDNS도 해석 확인 후 사용. 관찰된 direct/DERP 경로 기록; 항상 direct라고 추정하지 않음 |
| 옵션 기본 끔→테일넷만 켬→끔·VPN 해제 | 기본 차단, 켜면 선택된 VPN 인터페이스/주소로만 접속. 끔/해제 시 기존 guest 종료·주소 제거. 일반 LAN/공개 인터넷·다른 VPN·셀룰러 CGNAT 요청 차단, host WS는 계속 loopback 전용 |
| 주소/설정 | tun0 등 실제 인터페이스·100.64/10 주소 선택 확인, LOHS 주소/QR과 구별. 실제 수신 주소를 식별 못하면 실패로 기록하고 gate를 넓히지 않음 |
| 사설망·브라우저 | 공유 상대→Galaxy 포트 정책·공유 노드 격리 확인, HTTP 비보안 컨텍스트 폴백 정상. sessionToken·hello/snapshot 복귀·기내 LAN/솔로 회귀 |

## 결과 기록 — 2026-09-29 사용자 제공

| 날짜·검증자 | 버전·기기·망 | 항목·소요/오류·비밀 제거 첨부 | 판정 |
|---|---|---|---|
| 2026-09-29 · 사용자 | Windows 호스트 Tailscale Funnel `--https=443` → WSL Docker `relay-dev` 17777. 앱/브라우저·OS 상세 버전·commit·표본 수 미제공 | 공개 URL로 게스트 WebSocket 접속 성공. 게스트→호스트 hello·호스트→게스트 welcome 왕복 약0.5초. `{"t":"relay","peer":...}` 상태 프레임 정상 | **기본 WebSocket 통과 조건 해소**. 지연은 해당 시험의 관찰값이며 p50/p95·SLA 아님 |
| 2026-09-29 · 사용자 | 같은 환경의 프록시 경유 host 접속 | `host requires loopback`, 1008 거절. 현재 relay-dev의 루프백 호스트 제한 확인 | **원격 host는 미지원**. NP-RP-01의 토큰 기반 호스트 인증으로 대체 필요, Funnel WS 통과 실패와 구별 |
| 2026-09-29 · 사용자 | 같은 Funnel 노드 | 관리 콘솔에서 `funnel` 노드 속성 승인 1회 필요. 시험 후 funnel off | 승인 절차·시험 종료 기록 |
| 미실시/결과 미제공 | 강화된 원격 중계·Galaxy/iPhone/Mac 전체 경로 | 토큰 인증·room query·장시간 연결·재접속·PC 재부팅·실제 게임/정산·기내 회귀 | 후속 수용 검증 대기 |

위 결과는 사용자가 전달한 시험 기록이며 에이전트가 재실행하지 않았다. hello/welcome 왕복 성공을 프록시 경유 host의 성공으로 확대 해석하지 않는다. 공개 URL·토큰은 기록하지 않는다.
