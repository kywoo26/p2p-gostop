# M0 실기기 테스트 — 핫스팟 스모크 (AC-00)

- 대상 빌드: GitHub Releases의 `v0.0.x` (앱 화면 맨 위 "빌드 … · git 1234abc"로 확인). **회차 2는 `v0.0.2` 이상**(아래 "회차 2 체크리스트")
- 목적: 프로젝트 최대 리스크(spec 11.1, 리스크 R1) 확인. **비행기 모드에서 삼성 폰이 로컬 핫스팟을 켜고, iPhone Safari가 그 폰의 내장 서버에 붙는가.**
- 소요 시간: 약 20~30분
- 준비물
  - 호스트: 삼성 Galaxy (Android 16), 충전 50% 이상
  - 게스트: iPhone (iOS 26.5), 기본 카메라 앱과 Safari
  - 두 폰을 1m 안에 둔다.
  - **Galaxy의 VPN 앱을 끈다**(보안 폴더·백신 앱의 VPN, 광고 차단 VPN 포함). 빠른 설정이나 상단 알림에 열쇠 모양 아이콘이 없으면 꺼진 것입니다. 회차 1에서 VPN 주소(`tun0 10.5.0.2`)가 핫스팟 주소로 잘못 잡혔습니다. `v0.0.2`부터는 앱이 VPN 주소를 거르지만, 확인을 위해 끄고 시작합니다.

> 결과를 모르는 단계가 있어도 괜찮습니다. 멈춘 지점과 화면에 보인 문구, 그리고 **로그 공유**만 보내 주시면 원인을 가를 수 있습니다.

## 0. 설치 (처음 한 번)

1. Galaxy에서 브라우저(삼성 인터넷 또는 Chrome)를 열고 `github.com`에 로그인합니다(비공개 저장소라 로그인이 필요합니다).
2. 저장소 페이지 → 오른쪽 **Releases** → 가장 위 버전(예: `v0.0.1`) → **Assets** → `p2p-gostop-v0.0.1.apk`를 누릅니다.
3. 다운로드가 끝나면 알림이나 "내 파일 → 다운로드"에서 APK를 엽니다.
4. "출처를 알 수 없는 앱" 차단 화면이 나오면 **설정 → 이 출처 허용**을 켜고 뒤로 가서 **설치**를 누릅니다.
5. Play 프로텍트 경고가 나오면 **세부정보 더보기 → 무시하고 설치**를 누릅니다(개인 서명 앱이라 나오는 경고입니다).
6. 앱 이름 **맞고 P2P**를 엽니다. 맨 위에 빌드 번호와 git 해시가 보이면 성공입니다.
7. **권한 허용** 버튼(또는 핫스팟 시작 시 뜨는 안내)에서
   - "주변 기기(근처 Wi-Fi 기기)" → **허용** (필수, 위치 정보는 쓰지 않습니다)
   - "알림" → **허용** (권장. 거부해도 동작합니다)

업데이트 설치: 새 버전 APK를 같은 방법으로 받아 설치하면 덮어쓰기됩니다(같은 서명 키).

## A회차. 비행기 모드 ON (가장 중요)

### Galaxy (호스트)
1. 빠른 설정에서 **비행기 모드 ON**.
2. 빠른 설정에서 **Wi-Fi ON** (비행기 모드여도 Wi-Fi는 다시 켤 수 있습니다). 어떤 Wi-Fi에도 연결하지 않아도 됩니다.
   - **VPN이 꺼져 있는지** 한 번 더 확인합니다(열쇠 아이콘 없음). 켜져 있으면 끄고 결과표 비고에 적습니다.
3. 앱에서 **핫스팟 시작**을 누릅니다.
4. 몇 초 안에 상태가 **"핫스팟 실행 중"**으로 바뀌고 아래가 보이는지 확인합니다.
   - Wi-Fi 이름 `AndroidShare_1234` 같은 이름, 비밀번호 15자, `IP: 192.168.x.x · 포트 17777` 같은 주소
   - QR 두 개: ① Wi-Fi 연결용, ② 주소(URL)용
   - 상단 알림에 "맞고 P2P 핫스팟 실행 중"
   - 앱의 **"이 폰의 IPv4 주소"** 목록에 `swlan0` 같은 줄이 있고, 위의 `IP:`가 그 주소와 같은지 봅니다(`tun0`, `p2p-…` 주소면 ×).
5. **실패하면** 상태 줄의 오류 문구(예: `ERROR_GENERIC(2)`, `ERROR_INCOMPATIBLE_MODE(3)`)를 결과표에 적고, 아래 **로그 공유(15번)**를 한 다음 **C회차(폴백)**로 갑니다.
   - 실패해도 서버는 폴백용으로 켜 둡니다. 버튼이 **"서버 중지(폴백 종료)"**로 바뀌고 상단 알림에도 "핫스팟 실패 · 폴백 서버 유지 중"이 보이면 정상입니다(`v0.0.2`부터).

### iPhone (게스트)
6. 기본 **카메라** 앱으로 Galaxy 화면의 **① Wi-Fi QR**을 비춥니다 → 노란 배너 **"'AndroidShare_…' 네트워크에 연결"**을 누르고 **연결**.
7. "인터넷 연결 없음" 시트나 로그인 화면이 뜨면 **반드시 "인터넷 없이 사용"**을 누릅니다(**"취소"를 누르면 연결이 끊깁니다**). 아무 것도 안 뜨는 것도 정상입니다.
   - **시트가 떴는지 "예/아니오"로 결과표 6번에 적습니다**(떴다면 화면에 보인 버튼 이름도). 로그에는 남지 않아 직접 적어 주셔야 합니다.
   - 설정 → Wi-Fi에서 `AndroidShare_…` 아래에 "인터넷 연결 없음"이 보이고 체크 표시가 유지되면 정상입니다.
8. 카메라로 **② 주소 QR**을 비춥니다 → 배너 `192.168…`를 눌러 Safari로 엽니다.
   - 큰 글씨 **"연결 성공"** 페이지가 보이면 AC-00 핵심 통과입니다.
   - 페이지 표에서 `보안 컨텍스트`, `navigator.wakeLock` 값을 결과표에 적습니다(예상: `false`, `undefined`). **표에 보이는 글자를 그대로** 적으면 됩니다.
   - 페이지가 안 열리면: 주소창에 Galaxy에 표시된 주소를 **`http://`까지** 그대로 입력해 봅니다. "안전하지 않은 연결" 경고가 나오면 **웹사이트 보기**.
9. 페이지의 **WS 에코 테스트**를 5번 누릅니다 → "왕복 시간: NN ms"가 바뀌는지 확인하고 가장 큰 값을 적습니다.
   - Galaxy 앱의 진단에서 **WebSocket 접속 수: 1**을 확인합니다.
10. **잠금·복귀**: iPhone 측면 버튼으로 화면을 끄고 **10초** 뒤 잠금 해제 → Safari 페이지 아래 로그에 `화면 복귀` → `WS 열림`이 찍히는지 확인 → **WS 에코 테스트** 다시 누르기. 이어서 **1분** 잠금 후 한 번 더.
11. **호스트 백그라운드(선택)**: Galaxy에서 홈 버튼으로 앱을 내려 두고 1분 기다린 뒤 iPhone에서 **WS 에코 테스트**. 응답이 오면 포그라운드 서비스가 유지되는 것입니다. 다시 앱을 엽니다.
12. **호스트 화면 끄기**: Galaxy **전원 버튼**을 한 번 눌러 화면을 끕니다(앱은 켜 둔 채). **1분** 기다린 뒤 iPhone에서 **WS 에코 테스트**를 누릅니다.
    - 응답이 오면 ○. 안 오면 **다시 연결** 버튼을 누르고 다시 에코. 그래도 안 되면 ×.
    - Galaxy 화면을 켜고(잠금 해제) 앱 상태가 여전히 "핫스팟 실행 중"인지, iPhone이 여전히 `AndroidShare_…`에 붙어 있는지(설정 → Wi-Fi) 적습니다.
13. iPhone 페이지의 **로그를 호스트로 보내기**를 누릅니다. 페이지 아래 로그에 "호스트가 로그를 받았습니다 (N바이트)"가 찍히면 성공입니다. "거절했습니다(너무 잦음)"이면 5초 뒤 다시 누릅니다.

### 로그 공유 (Galaxy)
14. **세션이 바뀌는지(선택)**: 앱에서 **핫스팟 중지** → **핫스팟 시작**을 한 번 더 하고, 새 Wi-Fi 이름·비밀번호가 앞과 다른지 적습니다(iPhone은 새 QR로 다시 연결).
15. 앱 아래쪽 **로그 공유** → 카카오톡(나에게 보내기)이나 메일로 보냅니다. `v0.0.2`부터는 **전체 로그가 파일**(`p2p-gostop-log-….txt`)로 첨부되고 본문에는 요약만 들어갑니다. 받는 앱이 파일만 보여 주거나 본문만 보여 줘도 괜찮습니다(둘 다 오면 가장 좋음). 공유가 안 되면 **로그 복사** 후 붙여 넣기.
16. **핫스팟 중지**를 누릅니다.

## B회차. 비행기 모드 OFF

A회차의 1번만 **비행기 모드 OFF**(모바일 데이터 켜져 있어도 됨)로 바꾸고 2~16번을 똑같이 합니다.
- 4번에서 `IP:`가 셀룰러 주소(`rmnet…`, `100.x.x.x`)가 아니라 `swlan0` 같은 핫스팟 주소인지 꼭 확인합니다.
iPhone은 이미 저장된 이전 `AndroidShare_…`에 붙지 않도록, 새로 뜬 QR로 다시 연결하세요(세션마다 이름·비밀번호가 바뀝니다).

## C회차. 폴백 (A 또는 B에서 핫스팟이 안 켜질 때. 회차 2에서는 성공해도 한 번)

1. Galaxy **설정 → 연결 → 모바일 핫스팟 및 테더링 → 모바일 핫스팟** 켜기(앱의 **핫스팟 설정 열기** 버튼으로 이동할 수도 있습니다).
   - 비행기 모드에서 켜지지 않으면 그 사실을 결과표에 적습니다(삼성 제한으로 알려진 부분).
2. iPhone을 그 핫스팟에 연결합니다(모바일 핫스팟 화면의 QR 코드 사용 가능).
3. 앱에서 **주소만 표시** → ② 주소 QR을 iPhone 카메라로 찍어 "연결 성공"까지 확인하고 A회차 9~15번을 합니다.
   - **주소만 표시**는 "주변 기기" 권한 없이도 됩니다(`v0.0.2`부터). 권한을 거부한 상태에서도 눌러 보고 결과를 비고에 적습니다.
   - 끝나면 **서버 중지(폴백 종료)** 버튼이나 알림의 같은 버튼으로 끕니다.
4. (추가) 두 폰이 같은 집 Wi-Fi에 붙어 있는 상태에서 **주소만 표시**로도 같은 확인을 해 볼 수 있습니다. 이때 서버는 그 Wi-Fi의 모든 기기에 열려 있으므로 확인이 끝나면 바로 끕니다.

## 문제 해결

| 증상 | 해볼 것 |
|---|---|
| `ERROR_INCOMPATIBLE_MODE(3)` | 시스템 "모바일 핫스팟"이 켜져 있으면 끄고 다시 시작. 앱이 화면에 떠 있는 상태에서 버튼을 눌러야 합니다. |
| `ERROR_GENERIC(2)` / `ERROR_NO_CHANNEL(1)` | Wi-Fi를 껐다 켜고 다시 시작. 반복되면 로그 공유 후 C회차. |
| 권한 거부 후 버튼이 안 먹음 | 앱의 설정 열기 → 권한 → 주변 기기 → 허용 (**주소만 표시**는 권한 없이도 됩니다) |
| `IP:`가 `10.5.x.x` 등 VPN 주소로 보임 | VPN 앱을 끄고 **서버 중지** → **핫스팟 시작**. 결과표 비고에 VPN 앱 이름 |
| 핫스팟 실패 후 다시 시작하고 싶음 | **서버 중지(폴백 종료)** → **핫스팟 시작** |
| iPhone이 QR을 인식하지 못함 | 설정 → Wi-Fi에서 Galaxy에 표시된 이름을 고르고 비밀번호를 직접 입력 |
| Safari가 안 열리거나 오래 걸림 | 주소창에 `http://`를 포함한 전체 주소 입력. iPhone이 핫스팟에 연결돼 있는지 설정에서 확인 |
| 에코가 멈춤 | 페이지의 **다시 연결** 버튼 → 에코 다시. 결과표 비고에 적기 |
