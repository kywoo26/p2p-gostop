## 3. 측정 방법

- `tools/sim` match 모드: **중복(duplicate) 쌍** — 쌍 j마다 같은 셔플·같은 선으로 두 판을 두고 A가 좌석 0과 1에 한 번씩 앉는다(좌석 교대 + 패 운 상쇄). 판마다 나가리 배수 1.
- 승률 = A 승 / (A 승 + B 승). 나가리는 분모에서 뺀다(나가리 비율은 별도 표기). 95% 신뢰구간은 정규 근사.
- 시드: 모든 벤치마크 `--seed 1`(셔플 `mixSeed(1, 쌍, 0xdea1)`, 정책 `mixSeed(1, 판, 좌석, 0x901c)`). 휴리스틱 좌표 탐색은 후보마다 `--seed 100, 101, …`.
- 결정 시간은 합법 수가 2개 이상인 결정만 잰다(1개면 즉시 반환). 벤치마크 표의 시간은 20워커 동시 실행(코어 경합) 값이고, 5.2절이 단독 실행 값이다.
- 모든 수치는 Docker `node:24-bookworm-slim`(Node 24.21.0), WSL2, 20 논리 코어.

## 6. 격차와 다음 단계 (M2 당시 기록)

**현재 격차**: 보통 상대 −3.6%p(61.4% / 65%), 쉬움 상대 −0.9%p(79.1% / 80%, 신뢰구간 안).

**왜 승률에 천장이 있는가 (맞고의 운)**
- 같은 정책끼리도 패 운으로 승패가 크게 갈린다. 롤아웃 휴리스틱은 **무작위 정책에게도 22%를 진다**(78.0%, 10,000판). 쉬움은 가중 랜덤이라 무작위와 가깝고(쉬움 vs 무작위 57.1%), 상용급 vs 쉬움 79.1%는 이 천장(무작위 상대 ~80% 초반)에 거의 닿아 있다. 80%를 안정적으로 넘기려면 무작위 상대 승률 자체를 끌어올릴 만큼 강해져야 한다.
- 승률은 고/스톱 성향에도 좌우된다. 항상 스톱하면 승률이 +2.7%p 오르지만 돈은 잃는다(반복 0). 상용급은 AI-06대로 **점수 기대값**을 최대화하므로 이길 판을 크게 이기려고 고를 부르고(3고 이상 105판), 그만큼 역전패 위험을 진다. 판당 순액으로 보면 상용급은 보통 상대 +23.2점/판으로 압도적이지만, AC-03의 지표는 승률이다.
- 보통(1수 그리디)과 휴리스틱의 차이가 작다(휴리스틱 vs 보통 53.5%). 즉 "보통"도 기본기는 갖췄고, 추가 우위는 탐색이 찾는 수 %p에서 나온다. 2,000판의 95% 신뢰구간이 ±2.1%p라 조정 한 단계의 효과(1~3%p)를 확인하려면 판 수가 많이 든다.

**격차를 줄일 다음 단계 (효과 기대 순)**
1. **롤아웃 정책 강화**: 탐색 품질의 상한은 롤아웃이다. 반복 3에서 휴리스틱 가중치 하나(combo.score)로 +1.9%p를 얻었다. 휴리스틱에 뻑 위험(바닥 1장 + 뒤집기 같은 월), 쪽 기대(버린 패를 뒤집기로 먹을 확률), 짝패 보존, 상대 흔들기 월 추정을 넣는다.
2. **상대 모델링**: 지금 결정화는 모르는 카드를 균등하게 나눈다. 상대가 낸 카드·안 먹은 바닥 카드(먹을 수 있었다면 먹었을 것)로 상대 손패 분포에 가중치를 주면(베이지안 결정화) 표본 효율이 오른다. 흔들기로 공개된 카드는 이벤트에만 있고 뷰에는 없어서 엔진 API가 필요하다(보고서의 엔진 API 공백).
3. **기기 시간 예산 활용**: 단독 p95가 246ms라 예산 안에서 반복을 2~3배 늘릴 여유가 있다(UCT 기준 2000→4000회 +2.1%p). 순차 반감의 반복 상한을 기기별로 맞추는 적응형 예산(첫 결정에서 속도를 재고 1.0s의 70%까지 사용).
4. **평가 함수 컷오프와 가중치 학습**: 롤아웃을 끝까지 두는 대신 몇 수 뒤 평가 함수로 끊으면 반복이 늘어난다. 가중치는 좌표 탐색 대신 셀프플레이 결과로 회귀(로지스틱 회귀로 승패 예측)해 학습한다. 보통(그리디)이 쓰는 위험·노출 가중치는 아직 한 번도 조정하지 않았다.
5. **승률 지향 고/스톱 여유**: AC-03만 보면 evMargin을 올려(더 보수적으로) 승률을 사고 기대값을 조금 버릴 수 있다. 다만 AI-06의 취지(기대값 기반)와 맞바꾸는 것이라 결정이 필요하다.
6. **엔진 `reduce` 비용**: 롤아웃 시간의 절반 이상이 엔진의 합법 수 재검증과 점수 비교(`JSON.stringify`)다. 검증 없는 적용 경로가 있으면 같은 시간에 반복이 약 1.5~2배.

## 8. M6 후속: 적용 경로·밀기 (AI-02·AI-03·AI-08)

### 8.1 합법 수 적용 경로

`rollout`, 그리디 확장, ISMCTS 확장·고/스톱 EV, `playRound`는 `legalActions` 또는 `playerView.legal`에서 얻은 수를 엔진 `applyUnchecked`로 적용한다. 비교용 `debugReduce` 옵션을 켜면 같은 위치에서 `reduce`를 사용한다. 시드를 고정한 fast-check 롤아웃 속성 테스트(72판), 판 전체 액션·이벤트 비교(16판), 그리디·ISMCTS 선택 비교가 두 경로의 동등성을 확인한다.

Docker Node 컨테이너에서 `./dev.sh npm run bench -w packages/ai -- 2000`을 실행했다. 두 경로를 예열하고 같은 시드·가중치로 세 번씩 교대 측정한 중앙값이다. 한 반복은 한 판의 휴리스틱 롤아웃, 탐색 반복은 상용급 순차 반감의 후보 평가 한 번이다.

| 측정 | `reduce` 반복/초 | `applyUnchecked` 반복/초 | 속도비 |
|---|---:|---:|---:|
| 판 전체 롤아웃(분배 포함) | 8,096.7 | 9,645.2 | ×1.19 |
| 상용급 순차 반감 탐색 | 10,232.8 | 11,134.3 | ×1.09 |

탐색에는 결정화·휴리스틱·점수 평가도 포함되므로 적용 단계만 바꾼 효과는 M2 당시의 예상(×1.5~2)보다 작았다. 실기기 응답 시간과 AI 강도는 이 벤치로 재판정하지 않는다.

### 8.2 밀기 선택

엔진은 판 종료 뒤 승자에게만 `push`를 제공하고, 정산을 받는 선택에는 액션이 없다. `Policy.decidePush(view, ctx)`가 `true`이면 `playRound`가 밀기를 적용하고, `false`이면 정산을 확정한다. 쉬움은 낮은 정산(14점 이하)에서 첫 밀기만 고른다. 보통·상용급은 현재 정산 수령액과 다음 판을 받거나 밀었을 때의 기대 순액을 같은 시드의 휴리스틱 롤아웃으로 비교한다(각각 8/16표본). 잔액의 올인 상한, 이미 걸린 밀기 배수, 엔진의 연속 2회(×4) 상한을 반영한다. 난수는 주입한 `Rng`만 사용한다. 세션의 `nextPushes`와 마지막 `Settled` 사용은 `tools/sim` 테스트로 확인한다.

세션 진행기는 판 시작 잔액을 넘기고 밀기 결정 전에 이번 판의 즉시 정산을 반영한다. 다른 호출자가 잔액을 넘기지 않으면 정책은 상한 없는 기대값으로 판단한다. 판 종료 선택은 일반 `decide`가 아니라 `decidePush`로 호출해야 한다.

가중치 파일과 AC-03 강도 조정은 이번 후속에서 변경하지 않았다.
