## 3. 측정 방법

- `tools/sim` match 모드: **중복(duplicate) 쌍** — 쌍 j마다 같은 셔플·같은 선으로 두 판을 두고 A가 좌석 0과 1에 한 번씩 앉는다(좌석 교대 + 패 운 상쇄). 각 판은 독립 평가 단위라 나가리 배수 1로 시작하고, 승자는 밀기 대신 정산을 받는다. 밀기를 포기한 점수만 기록하고 후속 배수를 잃는 일을 막는다. 밀기 포함 순액·정산 분포는 아래 머니 모델처럼 session 모드로 측정한다.
- 승률 = A 승 / (A 승 + B 승). 나가리는 분모에서 뺀다(나가리 비율은 별도 표기). 95% 신뢰구간은 정규 근사.
- 시드: 모든 벤치마크 `--seed 1`(셔플 `mixSeed(1, 쌍, 0xdea1)`, 정책 `mixSeed(1, 판, 좌석, 0x901c)`). 휴리스틱 좌표 탐색은 후보마다 `--seed 100, 101, …`.
- 결정 시간은 합법 수가 2개 이상인 결정만 잰다(1개면 즉시 반환). 벤치마크 표의 시간은 20워커 동시 실행(코어 경합) 값이고, 5.2절이 단독 실행 값이다.
- 모든 수치는 Docker `node:24-bookworm-slim`(Node 24.21.0), WSL2, 20 논리 코어.

## 6. 격차와 다음 단계 (M2 당시 기록)

**현재 격차**: 보통 상대 −3.6%p(61.4% / 65%), 쉬움 상대 −0.9%p(79.1% / 80%, 신뢰구간 안).

**왜 승률에 천장이 있는가 (맞고의 운)**
- 같은 정책끼리도 패 운으로 승패가 크게 갈린다. 롤아웃 휴리스틱은 **무작위 정책에게도 22%를 진다**(78.0%, 10,000판). 쉬움은 가중 랜덤이라 무작위와 가깝고(쉬움 vs 무작위 57.1%), 상용급 vs 쉬움 79.1%는 이 천장(무작위 상대 ~80% 초반)에 거의 닿아 있다. 80%를 안정적으로 넘기려면 무작위 상대 승률 자체를 끌어올릴 만큼 강해져야 한다.
- 승률은 고/스톱 성향에도 좌우된다. 항상 스톱하면 승률이 +2.7%p 오르지만 돈은 잃는다(반복 0). 상용급은 AI-06대로 **점수 기대값**을 최대화하므로 이길 판을 크게 이기려고 고를 부르고(3고 이상 105판), 그만큼 역전패 위험을 진다. 판당 순액으로 보면 상용급은 보통 상대 +23.2점/판으로 압도적이지만, AC-03의 지표는 승률이다.
- 보통(1수 그리디)과 휴리스틱의 차이가 작다(휴리스틱 vs 보통 53.5%). 즉 "보통"도 기본기는 갖췄고, 추가 우위는 탐색이 찾는 수 %p에서 나온다. 2,000판의 95% 신뢰구간이 ±2.1%p라 조정 한 단계의 효과(1~3%p)를 확인하려면 판 수가 많이 든다.

**격차를 줄일 다음 단계 (효과 기대 순)**
1. **롤아웃 정책 강화**: 탐색 품질의 상한은 롤아웃이다. 반복 3에서 휴리스틱 가중치 하나(combo.score)로 +1.9%p를 얻었다. 휴리스틱에 뻑 위험(바닥 1장 + 뒤집기 같은 월), 쪽 기대(버린 패를 뒤집기로 먹을 확률), 짝패 보존, 상대 흔들기 월 추정을 넣는다.
2. **상대 모델링**: 지금 결정화는 모르는 카드를 균등하게 나눈다. 상대가 낸 카드·안 먹은 바닥 카드(먹을 수 있었다면 먹었을 것)로 상대 손패 분포에 가중치를 주면(베이지안 결정화) 표본 효율이 오른다. 흔들기로 공개된 카드는 이벤트에만 있고 뷰에는 없어서 엔진 API가 필요하다(보고서의 엔진 API 공백).
3. **기기 시간 예산 활용**: 단독 p95가 246ms라 예산 안에서 반복을 2~3배 늘릴 여유가 있다(UCT 기준 2000→4000회 +2.1%p). 순차 반감의 반복 상한을 기기별로 맞추는 적응형 예산(첫 결정에서 속도를 재고 1.0s의 70%까지 사용).
4. **평가 함수 컷오프와 가중치 학습**: 롤아웃을 끝까지 두는 대신 몇 수 뒤 평가 함수로 끊으면 반복이 늘어난다. 가중치는 좌표 탐색 대신 셀프플레이 결과로 회귀(로지스틱 회귀로 승패 예측)해 학습한다. 보통(그리디)이 쓰는 위험·노출 가중치는 아직 한 번도 조정하지 않았다.
5. **승률 지향 고/스톱 여유**: AC-03만 보면 evMargin을 올려(더 보수적으로) 승률을 사고 기대값을 조금 버릴 수 있다. 다만 AI-06의 취지(기대값 기반)와 맞바꾸는 것이라 결정이 필요하다.
6. **엔진 `reduce` 비용**: 롤아웃 시간의 절반 이상이 엔진의 합법 수 재검증과 점수 비교(`JSON.stringify`)다. 검증 없는 적용 경로가 있으면 같은 시간에 반복이 약 1.5~2배.

## 8. M6 후속: 적용 경로·밀기 (AI-02·AI-03·AI-08)

### 8.1 합법 수 적용 경로

`rollout`, 그리디 확장, ISMCTS 확장·고/스톱 EV, `playRound`는 `legalActions` 또는 `playerView.legal`에서 얻은 수를 엔진 `applyUnchecked`로 적용한다. 비교용 `debugReduce` 옵션을 켜면 같은 위치에서 `reduce`를 사용한다. 시드를 고정한 fast-check 롤아웃 속성 테스트(72판), 판 전체 액션·이벤트 비교(16판), 그리디·ISMCTS 선택 비교가 두 경로의 동등성을 확인한다.

Docker Node 컨테이너에서 `docker compose run --rm dev npm run bench -w packages/ai -- 2000`을 실행했다. 두 경로를 예열하고 같은 시드·가중치로 세 번씩 교대 측정한 중앙값이다. 한 반복은 한 판의 휴리스틱 롤아웃, 탐색 반복은 상용급 순차 반감의 후보 평가 한 번이다.

| 측정 | `reduce` 반복/초 | `applyUnchecked` 반복/초 | 속도비 |
|---|---:|---:|---:|
| 판 전체 롤아웃(분배 포함) | 8,096.7 | 9,645.2 | ×1.19 |
| 상용급 순차 반감 탐색 | 10,232.8 | 11,134.3 | ×1.09 |

탐색에는 결정화·휴리스틱·점수 평가도 포함되므로 적용 단계만 바꾼 효과는 M2 당시의 예상(×1.5~2)보다 작았다. 실기기 응답 시간과 AI 강도는 이 벤치로 재판정하지 않는다.

### 8.2 밀기 선택

엔진은 판 종료 뒤 승자에게만 `push`를 제공하고, 정산을 받는 선택에는 액션이 없다. `Policy.decidePush(view, ctx)`가 `true`이면 `playRound`가 밀기를 적용하고, `false`이면 정산을 확정한다. 쉬움은 낮은 정산(14점 이하)에서 첫 밀기만 고른다. 보통·상용급은 현재 정산 수령액과 다음 판을 받거나 밀었을 때의 기대 순액을 같은 시드의 휴리스틱 롤아웃으로 비교한다(각각 최대 8/16표본). 시간 제한이 있으면 첫 공통 표본 쌍을 마친 뒤 쌍 사이마다 시계를 확인하고, 완료한 표본만으로 선택한다. 잔액의 올인 상한, 이미 걸린 밀기 배수, 엔진의 연속 2회(×4) 상한을 반영한다. 난수는 주입한 `Rng`만 사용한다. 세션의 `nextPushes`와 마지막 `Settled`, 후속 판 배수는 `tools/sim` 테스트로 확인한다.

세션 진행기는 판 시작 잔액을 넘기고 밀기 결정 전에 이번 판의 즉시 정산을 반영한다. 다른 호출자가 잔액을 넘기지 않으면 정책은 상한 없는 기대값으로 판단한다. 판 종료 선택은 일반 `decide`가 아니라 `decidePush`로 호출해야 한다.

가중치 파일과 AC-03 강도 조정은 이번 후속에서 변경하지 않았다.

## 9. 고/스톱 과감성 재조정 (AI-03·AI-06·AI-07·AI-08, plan §1.5)

2026-09-29, 기준 `ca66ce9`, `ai/gostop-boldness`. 위 1~7절은 M2 당시 기록이며 이번 측정과 엔진 버전·실행 환경이 다르다. 사용자 피드백은 “스톱을 너무 빨리 한다. 조금 더 똑똑하고 과감해도 된다.” 추가 인터뷰 결정에 따라 솔로 신규 설정의 기본 난이도를 **상용급**으로 바꾼다. 이미 저장한 난이도는 기존 설정 정규화가 보존한다.

### 9.1 원인과 지표 정의

- 보통의 기존 `maxGo=1`은 1고 뒤 다음 고/스톱 선택에서 무조건 스톱한다. `minTurns=5`, 상대 점수 4·잠재력 5도 일찍 멈추게 한다. 문턱은 전략 가중치이며 게임 규칙이 아니다.
- 상용급 `analyzeGoStop`은 이미 `terminalPoints` → 엔진 `settle.finalPoints`를 사용한다. `evaluator.ts`의 미완성 족보 점수나 탐색의 승률 혼합 `utility`를 고/스톱 EV로 쓰지 않는다. 고 배수·피박·광박·고박은 이미 포함되어 있다. 양의 점당 금액이 일정하면 **정산점 EV 비교와 냥 EV 비교는 동일**하므로 단위 변경만으로 과감해지지는 않는다.
- 기존 롤아웃은 자기 다음 선택도 1고 상한·양측 카드 잡음으로 진행했다. 더 고할 기회가 EV에 반영되지 않을 수 있다. 다만 잡음이 항상 EV를 낮춘다고 단정하지 않는다. 아래 전후 수치는 정책 전체의 변화이며 각 요소의 독립적 인과 효과는 아니다.
- 표준 맞고의 나는 점수는 **7점**(규칙 정본 §12.5 G1). “3점 즉시 스톱” 선택 기회는 없으므로 `firstThreeStop.rate=null`(해당 없음)이다. 0%로 표시하지 않는다.

`tools/sim`은 정책에 넘긴 공개 뷰와 반환 액션만 관찰하며 난수를 추가로 쓰지 않는다. 스톱 점수는 배수 전 족보 `score.total`, 상대 잠재력은 같은 `DEFAULT_WEIGHTS.combo` 척도(확률 아님), 피는 쌍피·보너스를 합산한 가치다.

| 지표 | 분모·해석 |
|---|---|
| 판별 고 횟수 0 / 1 / 2 / 3+ | 각 정책이 참여한 **모든 판**, 패배·나가리·총통 포함. 0고가 모두 스톱 선택을 뜻하지는 않는다 |
| 7점 첫 선택 즉시 스톱 | `goCount=0 && score=7`인 선택 중 스톱 수 / 선택 기회 수 |
| 1고 후 스톱 | `goCount=1`인 다음 선택에서 스톱 수 / 선택 기회 수. 그 전에 역전패·나가리한 판은 이 분모에 없고 판별 고 횟수에는 있다 |
| 저위험 선택 스톱 | 상대 점수 ≤3·잠재력 <7, 내 피박/광박 위험 없음, 남은 내 턴 ≥2인 선택 중 스톱 비율. 전후 동일 기준 |
| 스톱 시 상태 | 내 점수·상대 점수 히스토그램, 상대 잠재력·피·남은 턴의 평균·백분위, 박 기회가 있던 스톱 수. 자동 스톱은 선택 비율에서 제외 |
| 승률 | 승 / (승+패), 나가리 제외. AC-03과 같은 정의 |
| 판당 순액(냥) | `(판 정산 + 즉시 정산) × 점당 / 전체 판 수`. 아래는 점당 100냥, 독립 판·상한 전 기대값. 실제 잔액 상한·밀기를 포함한 세션 수익률은 아님 |

### 9.2 선택한 정책과 비교 후보

보통·공용 롤아웃은 일반 상한 2고, 상대 점수 문턱 5, 상대 잠재력 문턱 9, 남은 턴 문턱 3을 쓴다. `bold>0`이면 상대 점수 <3·잠재력 <7이며 내 박 위험 없이 피박 기회(내 피 ≥8, 상대 피 ≤5, 규칙의 0장 예외 반영) 또는 광박 기회(내 광 ≥2, 상대 광 0)가 있을 때만 3고까지 허용한다. 내 피박/광박 위험과 상대 득점 위협이 겹치거나 다음 내 뒤집기까지 더미가 모자라면 받는다. 족보 완성 전 장수는 **가능성 신호**이며 실제 박 판정은 엔진 G6·G7만 한다.

상용급 EV는 `EV(go) > stop × (1 + evMargin × (1-bold))`를 사용한다. 기본 `bold=1`, `evMargin=0.1`이므로 순액 EV가 큰 쪽을 고른다. 승률 보상으로 바꾸거나 손실액을 할인하지 않는다. `bold=0`은 기존 규칙 정책 비교용이고, 양수에서 박 기회·위험 분기를 활성화한다. 고 EV 롤아웃에서 자기 카드 잡음은 `selfNoise=0`, 상대는 기존 `rollout.noise=0.3`이다. 고 이후 나가리가 되어도 이후 발생한 즉시 정산 순액은 평균에서 버리지 않는다. 기존 확정 즉시 정산은 양쪽 선택에서 공통으로 빼며, 비교는 지금 이후 순액만 대상으로 한다.

기본 반복 2,000회와 1,000ms 제한은 유지했다. 표본 확대는 모바일 비용을 늘리므로 이번에는 채택하지 않았다. 시간 제한 없는 모드는 같은 시드·상태에서 결정적이며, 시간 제한 모드는 완료한 표본 수가 기기 속도에 따라 달라진다.

| 보통 vs 쉬움, seed 1, 2,000판 | 승률 | 판당 순액(100냥/점) | 7점 즉시 스톱 | 1고 후 스톱 |
|---|---:|---:|---:|---:|
| 변경 전(1고·남은 5턴) | 70.61% | +1,052.90냥 | 354/497 (71.2%) | 338/338 (100%) |
| 후보: 2~3고·남은 2턴 | 65.85% | +1,987.05냥 | 134/467 (28.7%) | 216/923 (23.4%) |
| **채택: 2~3고·남은 3턴** | **68.46%** | **+1,730.35냥** | **165/460 (35.9%)** | **279/793 (35.2%)** |

남은 2턴 후보도 돈은 늘지만 승률이 4.76%p 하락한다. 남은 3턴 후보는 승률 하락을 2.16%p로 줄이면서 순액은 64.3% 늘고, 두 체감 스톱 비율이 크게 낮아져 채택했다. 승률과 순액이 동시에 증가했다고 해석하지 않는다.

### 10.1 사전 고정한 비교 방법

- 기준선: 상용급 2,000회, 보통/쉬움 각각 2,000판, seed 1. 과거 63.35%/77.02%를 새 측정으로 대체하지 않고 직접 재측정한다.
- 훈련: seed 100, 각 상대·예산 조합 400판. 예산 2,000/4,000 두 개만 비교한다. 롤아웃·공개 흔들기 정보·고/스톱 가중치는 동시에 조정하지 않는다. 상대 보통·쉬움은 같은 기본 정책이다.
- 검증: 후보 4,000회, seed 1, 상대별 2,000판. seed 1은 기존 공개 벤치마크와의 비교용이며 새로 비공개 추출한 시드는 아니다. 훈련 seed 100과 분리하고, 검증 결과를 본 뒤 후보를 추가 선택하지 않는다.
- 모든 강도 측정은 표준 규칙·독립 match·시간 제한 없음. 1,000개 중복 셔플 쌍에서 A 좌석 0/1 각각 1,000판을 둔다. 난수 파생은 §3과 동일하다. 승률은 승/(승+패), 나가리 별도, 95% 구간은 기존 도구의 정규 근사다. 중복 쌍 내 상관을 보정한 신뢰구간은 아니다.
- 판당 순액은 즉시 정산 포함·100냥/점·잔액 상한 전이며 분모는 나가리 포함 전체 판 수다. #106의 과감성은 유지한다. **AC-03 통과 지표는 순액이 아니라 승률**이며, 순액 개선만으로 미달을 통과 처리하지 않는다.
- Node 시간은 이 작업의 대량 측정과 빌드 종료 후 별도 단독 워커, seed 7, 각 예산·상대 60판, `--time-ms 1000`으로 확인한다. 합법 수 2개 이상 결정의 평균·p95·최대를 기록한다. 시간 제한 모드는 기기 속도에 따라 완료 표본 수가 달라지므로 강도 비교의 결정론 자료와 분리한다. Galaxy의 실제 1초 예산 충족 여부는 사람 검증 전까지 미검증이다.
- 제한된 재시도는 후보 1개에서 종료한다. 두 승률 점추정치가 모두 65%/80% 이상일 때만 통과 후보로 볼 수 있고, 하나라도 미달이면 기본 예산 2,000회와 P0 미완을 유지한다.

공개 흔들기 정보는 현행 `knowledge.ts`가 `revealed` 카드를 상대 손패에 고정하고 그 수만큼 미지 손패 표본 수를 줄이는 방식으로 이미 반영한다. 이번에는 그 축을 재구현하지 않고 반복 예산 증가가 현재 정책의 격차를 메우는지 확인한다. 반복 상한은 카드 선택의 순차 반감 예산과 고/스톱 EV 표본 수에 함께 적용된다. 따라서 이 비교는 카드 선택만의 효과를 분리하지 않으며, 고/스톱의 EV 문턱·과감성 가중치는 그대로다.

재현 진입점은 저장소 루트의 `/home/k/.local/bin/docker compose run --rm dev bash tools/sim/ac03-retry.sh <단계>`이며 단계는 `baseline`, `training`, `validation`, `timing`이다. 공유 머신 부하 지시에 따라 강도 워커는 최대 8로 고정하고 단계별로 하나씩 실행한다. 시간 측정은 항상 1이다. 원자료는 `tools/sim/results/ac03-retry/`에 저장한다. 지시 전 완료된 보통 기준선(16워커)·2,000회 훈련(4워커)은 보존했다. 당시 진행 중이던 쉬움 기준선과 4,000회 훈련은 중단하고 8워커로 처음부터 재측정했다(미완성 표본을 합산하지 않음). 워커 수는 결과에 영향을 주지 않으며, 다른 작업과 경합한 대량 실행의 결정 시간은 AI-05 판정에 사용하지 않는다.

환경: `p2p-gostop-dev:4`, Node 24.20.0 / npm 11.19.0, Docker 29.7.2, WSL2 Intel Core i7-14700K. 런타임 라이브러리 API·의존성·규칙 변경 없이 기존 CLI로 측정한다.
